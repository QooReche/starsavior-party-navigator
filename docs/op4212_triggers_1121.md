# 작전 42-12 조건부·발동형 효과 세부 동작 대조 (2026-11-21)

## 결론

- 내 정보 1121로 실제 장착된 스킬 레벨(프레이 7/7/7·패시브4, 왈츠 아세라 10/10/10·4, 프로페서M 7/8/8·4, 그웬 7/7/7·4)·잠재력 7종·적 2종(공허선도자·감시자)의 조건부 효과를 SE 표 단위로 전부 나열하고 PC 클라 26752678 `decompiled/`·`rebuild_26752678/T`와 하나씩 대조했음. 장비 세트(CLIENT_EQUIP_SET_OPTION_TEMPLET 12행)는 능력치만 있고 발동형 효과가 없음. 아르카나는 여정 전용이고 전투 효과는 잠재력(gauntlet)으로만 들어옴. 스타링크·궤적도 능력치뿐임(아래 F절).
- **클라와 달라서 고친 것 2건**(규칙 스위치, 기본 client·legacy 보존):
  1. `mc.se_cool_clock` — 재발동 제한(SeCoolTurn, «발동 후 N턴 재발동 불가»)을 주인의 **자기 턴 종료**마다 1씩 줄임. 엔진은 주인의 **행동 시작** 횟수로 세서, 남의 턴에 발동한 효과가 주인의 다음 턴 시작에 풀렸음(클라는 그 턴이 끝나야 풀림). 이 전투에서는 프로페서M 잠재력 〈날렵한 자세〉(특수기 뒤 게이지 +20%)가 해당.
  2. `mc.dispel_isbuff` — «강화효과 해제»·«약화효과 해제» 후보를 표의 IsBuff로 고름. 엔진은 IsBuff=false인 왈츠 아세라 〈협공 확률 20% 증가 (C)〉를 공허선도자 〈멸시〉가 지우고 개수도 소모했음.
- 작전 42-12(1000판·seed7) 클리어 비율: **고치기 전 대비 약 0.54배**(1번만으로 같은 폭, 2번은 1000판에서 변화 없음). 원값은 비공개 `role-private/op4212/triggers/`에만 둠.
- 사용자가 물은 «치명이 터지면 확률이 다시 돌아가는가»: 클라는 **대상마다 스킬 1회에 1번** 굴리고(모든 타격이 같은 결과), 추가 발동·협공·트리거 시전은 새 스킬이라 다시 굴림. «치명 시» 조건은 이번 스킬의 대상 중 하나라도 치명이면 참이고, 결과 목록은 모든 스킬 시작 때 전 유닛에서 비움. 엔진과 같음.
- 적이 거는 약화·해제·정화·면역, 구원자 절대 효과 저항(2000)도 별도 표로 대조했고 위 2건 외에는 엔진과 같음.

## E. 고친 것

### 1. 재발동 제한 시계 (`mc.se_cool_clock`, 기본 client·legacy legacy)

- 클라: SE 발동 판정(OBF_18609, NKM:16496-16538)은 쿨 확인 → 확률 → 조건 → 통과하면 OBF_31057로 SeCoolTurn 저장. 차감은 OBF_15627(NKM:3604-3617)뿐이고, 이는 유닛의 TURN_END 처리(OBF_22866, NKM:2013-2021)에서 버프 지속 차감 뒤 스킬 쿨과 함께 불림. TURN_END는 턴 유닛이 살아 있을 때만(NKM:13957-13966). 그 밖의 호출은 턴 유닛이 퇴장할 때(NKM:1111·1570-1574)와 등장 초기화(NKM:1930·3493-3499)뿐.
- 엔진 전: 발동 때 주인의 행동 횟수를 적고 «행동 횟수가 N 늘 때까지» 막음 → 남의 턴에 발동하면 주인의 다음 턴 **시작**에 풀리고, 자기 턴에 발동하면 그 턴이 끝나도 다음 턴 시작 전까지 막혔음.
- 엔진 후: 유닛마다 자기 턴 종료 횟수(`turn_ends`, 턴 종료 블록 끝 1592)를 세고 그것으로 판정. 남의 턴에 발동하면 주인의 다음 턴이 **끝날 때**까지 막힘.
- 이 전투 영향: 〈날렵한 자세〉 발동 횟수가 줄어 프로페서M 게이지 가속이 줄어듦(횟수는 비공개 계측). 아세라·그웬 EX5는 «내 턴» 조건이라 두 시계 결과가 같음.
- 시험: `tests/op4212_triggers_test.py` SeCoolClockTest 5건. `_recast_clock`을 행동 횟수로 되돌리는 변이에서 2건 실패 확인 후 원복.

### 2. 강화/약화 해제 후보의 IsBuff (`mc.dispel_isbuff`, 기본 client·legacy legacy)

- 클라: 해제 후보(OBF_15506, NKM:4229-4253)는 `(OBF_9028 && DeleteDebuff) || (OBF_7714 && DeleteBuff)`이고 OBF_7714 = IsBuff && IsPositive, OBF_9028 = IsBuff && !IsPositive(NKM.Templets:40597-40618). CanNotDispel은 그다음에 뺌.
- 표: BI_DRESS_STRANIS_4(〈협공 확률 20% 증가 (C)〉)는 IsBuff 없음·IsPositive·CanNotDispel 없음.
- 엔진 전: 부여 줄의 분류(강화)만 봐서 위 효과를 지우고 «1개 해제»의 개수도 썼음. 후: `data/buff_count.json`(IsBuff·IsPositive 표, 동명 충돌 제외)으로 판정, 표에 없으면 기존 분류.
