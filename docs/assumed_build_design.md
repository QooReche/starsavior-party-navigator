# 육성 가이드 — 가정 편성 1단계

2026-11-10 심야 보완. 공통 재료와 작전·회랑을 구현했음. 실제 계정 자료를 쓰지 않았음.

## 11/10 심야 확정 변경

- 옵션은 「육성 가이드」 하나임. 옛 `equipment`·링크 `ae`는 무시함. `growth`·`owned`만 복원하고 shared 모드에서는 옵션·결과를 저장하지 않음. 정책 버전을 캐시·기록 서명에 넣어 이전 분리 시나리오 기록과 섞지 않음.
- 기본 묶음은 레벨(스타링크 가상 슬롯 등록)·가이드 기본 장비 +15·최대 스킬·공명 해금 최대·목표 여정/잠재력임. 자기 레벨과 원본 계정은 그대로 두고 대상의 평가 문맥에만 가상 슬롯을 넣음. 미보유도 레벨을 명시함. fixed200은 기존 계산기 규칙을 유지함.
- 항목별 비교는 레벨만/장비만/스킬만/공명·잠재력만임. 마지막 묶음에는 기존 목표 여정이 포함됨. 각각 해당 항목만 바꿔 동료를 재탐색하고 같은 보유 기준과 비교함. 합산하거나 순차 차감하지 않음. 실제 장비가 더 좋으면 음수도 그대로 남김.
- 7,200판·120초·최종 48시나리오 상한을 유지함. 묶음 상위 24개를 먼저 배정한 뒤 그 묶음의 항목별 비교, 나머지 묶음 순서로 남은 재평가 슬롯을 배정함. 미선발·시간 초과는 명시적으로 미평가임.
- 보정 카드에 라이트/다크 토큰의 점선과 카드 안 강조 라벨을 넣음. 수치 옆 별표 title은 원래 값→보정 값임. 팀 머리에 가정 포함, 표의 각 줄에도 같은 라벨을 표시함.

### 스타링크 슬롯 추천

- 현재 `star_link.slots` 배열 길이만 사용함. 빈 슬롯은 빈 칸 교체로 처리하고 소스는 별도임. 중복·알 수 없는 슬롯 구원자·소스와 슬롯 중복은 확인 부족으로 중단함. 레벨/슬롯 없는 옛 형식은 패널 대신 다시 불러오기 필요 칩을 표시함.
- 사용자가 실행을 완료한 일반 추천 콘텐츠의 결과만 메모리에 저장함. 자동 전체 계산·새 슬롯 해금·로컬스토리지 저장은 없음. 계정·전투 방식·규칙·제외·브레이크·데이터가 달라지면 문맥을 비움. 각 스테이지의 기믹·시즌·피해 가중치도 보관함.
- 신규 후보는 소스를 제외한 보유 구원자 중 레벨만 적용한 전투력 증가 상위 8명임. 기존 슬롯에서는 한 명씩 뺌. 1명 고정 재탐색 경로를 양쪽 상태에서 실행하고, 두 상태에서 발견한 공통 후보 집합을 예선 4판·최종 100판·같은 시드로 재평가함. 양쪽 최고를 비교하므로 새 팀 발견만으로 슬롯 이득이 생기지 않음. fixed200처럼 동일 입력이면 결과를 재사용함.
- 실제 넣기/빼기 교환 검증을 먼저 함. 개별 넣기 이득/빼기 손해 진단은 예산 절반 이내에서 이어서 계산함. 최대 3회 교환·24쌍·12,000판·120초임. 여러 번 교환하면 최초 슬롯과 직접 재검증하며 미완료면 첫 검증 교환만 유지함. 제한 탐색이므로 전역 최적을 보장하지 않음.
- 순서는 개선이 확인된 콘텐츠 종류 수, 동률이면 콘텐츠 ID 순으로 같은 콘텐츠의 개선폭 비교임. 다른 콘텐츠 수치를 더하거나 크기끼리 비교하지 않음. Wilson 차이 구간이 0을 포함하면 확인 부족임. 미평가 콘텐츠가 있거나 확인된 손해가 있으면 그 교환을 추천하지 않음. 구간은 탐색 후보 전체에 대한 다중비교 보정을 하지 않은 추정 범위임.
- 슬롯 쿨다운은 사용자 11/10 확정 요구에 따라 존재만 안내함. 입력에 DateTime이 없어 실제 교체 가능 시점은 계산하지 않음. 클라 실효 레벨 근거는 `docs/myinfo_format.md`의 NKC:501233-501265·421483-421504임. 서버의 fixed200과 소스 정확히 200 해금 상태는 미확인으로 유지함.

아래는 최초 1단계의 기록이며 옵션·묶음·표시 정책은 위 심야 변경으로 대체했음.

## 범위와 입력

- 내 정보 영역에 「육성 가이드(미보유·덜 키운 구원자 가정)」·「장비 가정(가이드 기본 세트 +15)」 두 옵션을 두었음. 기본 꺼짐. 육성 대상은 미보유만/보유 목표 육성 포함 중 선택함. (→ 이후 11/10 심야 육성 가이드 하나로 통합)
- 육성과 장비는 별도 시나리오임. 보유 육성은 공명·스킬·여정·특수 잠재력만 변경하고 각인·호감도·장비·일반 잠재력 등은 유지함. 장비 시나리오는 보유 한 명의 장비만 바꿈. 미보유는 각인·호감도 0과 목표 육성·가이드 장비를 사용함.
- `MyInfoReco.assume()`는 합성 유닛과 `source: owned/assumed`, `changedFields`, `presetId`만 만듦. `assumedProfile()`에서 콘텐츠 규칙을 정한 뒤 최종 능력치를 계산함. 원본 `MI.info`와 보유 프로필을 수정하지 않음.
- normal의 레벨은 계정 `star_link_level`, 공명은 그 레벨에서 해금된 최대임. fixed200의 레벨 200·공명 10·스타링크 제외 규칙은 기존 계산기를 그대로 거침. 슬롯별 최대 스킬은 전투 어댑터 단계 표에서 얻음.
- 합성 결과의 `missing`, 유한수, 스킬 슬롯·단계와 잠재력 ID·단계의 전투 어댑터 지원을 검사함. 미지원·누락은 평가 제외 사유로 남김. 빠진 계정 전술 값을 임의로 보충하지 않음.

## 공통 세팅과 근거 재확인

- `battlesim/starsavior/build.py:setting_spec()`로 기존 표준 세팅 정책을 모았음. `make_build()`는 같은 계산 결과를 기존 엔진 형식으로 투영함. 장비 각 부위의 주·부옵, 원시 여정, 잠재력은 별도 필드임. `make_build().gear`의 잠재력 상시 능력치를 장비에 복사하지 않음.
- `tools/build_growth.py:assumed_presets()`가 growth.json에 구원자별 세팅·부위/주옵별 +15 값·유효 item_id·부옵 정책·여정·잠재력·최대 스킬·허용 단계·출처·버전을 생성함. 공개 로스터 57명과 growth UID 57개 일치를 검사함. private 원문 표는 내보내지 않음.
- 장비는 PVE 첫 세트, 없는 구원자는 기존 클래스 기본값, T2 레전더리 +15 주옵과 평균 부옵임. 사설 표의 `EquipTier/EquipGrade/EquipType/SetOptionId/EquipMainStatType`에 일치하는 item_id를 사용하고 +15 값이 기존 databook 값과 같은지 검사함.
- 치명타 조건 분기와 넘친 치명 부옵 재분배는 표준 Lv200의 세팅을 고정했음. 실제 계정마다 장비를 최적화하는 기능은 아님. `setting_spec()`에 기존 정책이 한 벌만 있으며 계정 전술 변화로 프리셋 자체가 바뀌지 않게 한 선택임.
- 재확인한 코드: `myinfo_stats.js:final_stats()`의 normal/fixed200·공명 해금·장비 세트·잠재력 분리, `myinfo_reco.js:profile()`의 보유 전용 매핑, `party_template.html:runCore()`의 보유/속성 필터·`simParty()`의 최종 능력치 경로, `battlesim/starsavior/myinfo_combat.py:select_skills/apply_potentials()`의 지원 단계 검사임.
- `tests/myinfo_combat_test.py:test_all_roster_max_level_effects_match_existing_data`가 최대 스킬의 효과·실효 쿨과 기본 DB 일치를 확인함. 클라 전투 규칙 자체는 변경하지 않았음.

## 탐색과 비교

1. 기존 보유 예선·본선을 완료한 뒤 가정 단계를 실행함. 옵션 꺼짐이면 기존 시뮬 입력·서명 형식을 유지함.
2. 대상은 제외 목록·콘텐츠 속성 조건을 통과한 미보유 전원과 선택한 보유 육성·장비 시나리오임. 가정 구원자 한 명을 고정하고 보유 동료 풀에서 3명을 다시 조합함. 보유가 3명뿐이어도 생성하고, 보유 기준선이 없으면 개선폭은 비워 둠.
3. 동료 풀은 최대 16명임. 고정 구원자와의 연계·개인 점수 상위 6명, 기존 풀의 직업별 후보를 먼저 보충함. 조합마다 근사 점수, 배치·리더·브레이크를 다시 계산함.
4. 대상마다 quick 순위와 근사 순위에서 서로 다른 후보 2개를 남김. quick 하나로 탈락시키지 않음. 대상별 첫 후보를 전부 배치한 뒤 두 번째 후보를 배치하여 순서를 분산함.
5. 각 후보의 동료 3명에 보유자만 붙인 대조 팀도 검사함. 더 좋은 보유 팀을 발견하면 보유 기준 후보에 넣음. 예선은 4판, 선발은 최대 48개 시나리오임. 미선발은 「예선만·미평가」로 남김.
6. 선발 후보와 보유 기준 후보 최대 3팀을 새 시드 900001로 각각 100판 재평가함. 예선 시드는 17011임. 공통 난수만으로 오차가 없어지지는 않음. 재평가한 보유 최고를 기준으로 클리어 확률 차이(%p)를 계산함.
7. 기본 상한은 7,200판·120초임. 후보 생성 중에도 마감을 검사하고 조합 64개마다 제어권을 돌려줌. 기존 SIMQ 작업자 예산(최대 3개)을 재사용함. 제한·취소 시 완료한 팀만 수집하고 미평가를 0 개선으로 취급하지 않음. 화면 판 수는 완료한 팀 기준임.
8. 수동 모드도 예선은 오토로 선발하고 본선은 선택한 전투 방식으로 비교함. 수동 100판 비교에는 작업자의 자동 100판·정책별 33판×4·선택 정책 100판·재생 1판을 포함한 333판을 예산에서 차감함. 진행도·판별 배열은 수동 결과에서 가져옴. 정책 탐색 판 수 때문에 재평가 대상 수가 오토보다 적을 수 있음.

## 결과·기록·공유

- 대표 카드에 미보유/육성/장비 가정 배지와 바꾼 항목을 표시함. 「이 구원자를 키우면」 표에 음수를 포함한 클리어 개선폭, Wilson 구간 끝점을 사용한 차이 범위, 진행도·처치 턴·시행 수·후보 범위를 함께 표시함. 구간 하한이 양수일 때만 「개선 확인」으로 셈.
- 「성능 개선 기준 육성 후보」는 개선을 확인한 콘텐츠 종류 수, 같은 단위의 원 개선폭 순임. 투자 효율이라고 부르지 않으며 점수 단위가 다른 콘텐츠를 합산하지 않음.
- LS 도우미의 `growth.options`, `growth.history`를 사용함. 콘텐츠/스테이지별 최신 요약만 최대 30건 저장하며 판별 배열·합성 유닛·장비 원문을 저장하지 않음. 계정/엔진/데이터가 다른 기록은 집계에서 제외함. 저장 실패해도 현재 화면 결과를 유지함.
- 공유 링크에는 ag/ae/ao 옵션 상태만 추가함. 기존 계정 공유 payload는 원본 MI.info임. `MI.shared`면 육성 결과는 메모리에만 두고, 내 정보 삭제 때 육성 기록도 삭제함.
- 가정 캐시 서명은 계정 지문·옵션·대상·프리셋·콘텐츠·제외·브레이크·전투 방식·규칙·엔진/데이터 버전임. 옵션·계정·조건 변경은 실행 중 작업을 무효화함. MI.profiles 키에 계정·성장표 빌드·프리셋 버전을 추가했음.

## 2·3단계

- 2단계 길드 방어전: 보유 탐색 뒤 한 명 변경 탐색을 적용하고 상위 20% 점수 차이를 주 지표로 사용하기로 함. 단계·지원·평균·상한 도달률을 함께 기록함. 이번에 실행 경로는 연결하지 않았음.
- 3단계 코스모: 보스별 후보를 만든 뒤 가정 구원자를 3팀 전체에서 한 번만 사용하도록 재결합하기로 함. 이동한 보유자까지 포함한 3팀 합산 점수를 비교하고 시즌·난이도·순위 방식을 서명에 포함하기로 함. 이번에 실행 경로는 연결하지 않았음.
- 두 명 동시 육성·장비 재분배·재료 비용 산정은 범위 밖임. 제한 탐색 최고이며 전역 최적 보장은 하지 않음.

## 독립 리뷰 반영

고정 스냅샷 `1402784..f94484e`를 독립 리뷰했음. 보유 최고가 4판 대조 예선으로 덮이는 문제는 기존 최고를 최종 재평가에 반드시 남기는 방식으로 고쳤음. `hard` 후보의 생존 라운드 순서를 기존 quickRank와 맞췄음. 옵션 한글 원문을 복구하고 실제 라벨 검사를 추가했음. 후보 생성의 시간 상한·제어권 반환을 추가했음. 재검토 `f94484e..b2ca536`에서 발견한 부분 완료 경계도 고쳤음. 기존 최고의 새 시드 재평가가 없으면 다른 대조팀이 완료됐어도 개선폭을 만들지 않고 「기준 재평가 미완료」로 표시함. 다섯 지적 모두 반영했고 기각은 없음.
