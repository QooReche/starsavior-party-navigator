# 작전 42-12 과대평가 조사 (2026-11-21)

## 판정

**엔진 과대평가 원인은 아직 미해결임.** 결과창 대조 도구의 집계 혼용 1건은 고쳤음.
전투 규칙·계수·기본값·허용 목록·탐색·화면은 바꾸지 않았음.
클라 근거 없이 승률에 맞추는 보정은 넣지 않았음.

사용자가 보고한 약 20판 전패와 현재 입력의 시뮬 클리어 비율은 맞지 않음.
독립·동일 조건의 20판으로 간주하면 현재 시뮬 확률에서 전패할 확률은 약 **0.106%**임.
단, «약 20판»의 정확한 판 수·각 판 입력·중간 패치 여부를 별도로 기록한 자료는 없음.
5판의 패배 결과창이 시뮬 **패배 판** 분포에 대체로 들어온다는 사실로
전체 승패 분포까지 맞는다고 판단하지 않음.

## 먼저 재현한 차이

### 집계 혼용 수정

`ingame_check`의 총량 비교에는 이미 `battle_stat`이 있었지만, 턴당 비교에는
`per_unit.dmg/dmg_taken`을 넣고 있었음. 후자는 실제 HP 차감·보호막 흡수량이며
오버킬 등이 제외됨. 결과창 수치와 같은 정의가 아님.

NKM:7991–7996은 피해 적용 반환값과 별개로 계산 피해를 공격자/피격자 통계에 더함.
누적 구현은 NKM:2678–2686임. 이에 따라 턴당 비교도 `battle_stat`을 쓰도록 고쳤음.
출력에 `turn_damage_basis=battle_stat`과 아군 행동 수가 추정이라는 표시를 넣었음.
실제 전역 TURN만 쓰는 준 피해율도 추가했음.

회복 비교 역시 초과 회복을 포함한 기존 `healing.*.heal_raw` 정의를 따름.
NKM:15762–15764,5543–5547,2136–2139는 HP 상한 처리와 별개로 계산 회복량을 누적함.
새 관측 파일의 `heal`은 이 결과창 값이고 `heal_effective`가 실제 HP 회복량임.

첫 판 기준의 «받은 피해 약 21% 부족»은 이 혼용으로 커진 차이였음.
같은 200판·같은 분모에서 결과창 정의로 바꾸면 **약 11.3% 부족**임.
준 피해율은 약 **27.4% 과다**로 남음. 이는 첫 판 하나와 전체 시뮬 평균의 비교이며,
실제 아군 행동 수는 판독되지 않았으므로 «아군 1행동 피해 오류»로 확정할 수 없음.
이번 변경으로 승패나 실제 피해 계산이 좋아진 것은 아님.

### 5판을 따로 비교

아래 값은 **판마다 피해/TURN을 구한 뒤 평균**한 값의 비율임.
평균 피해를 평균 TURN으로 나눈 값과 구분함. 계정의 원값은 비공개 결과에만 저장했음.
5판의 최종 TURN은 하한만 있으므로 턴당 계산에서 제외했음.
3판 TURN은 흐려 잠정 사용했으며, 이를 빼는 민감도도 함께 기록했음.
5판 그웬 받은 피해는 1판과 같은 판독값이라 구원자별 평균에서는 제외했음.
5판 피해 합계 자체도 이 불확실성을 포함하므로 확정값으로 보지 않음.

|준 피해 총량, 5판|1.158|1.039|

받은 피해율 **0.910**임. 판독 선택에 민감하므로 7%·9%를 고정 엔진 보정량으로 쓰면 안 됨.

프로페서M **0.960**, 그웬 **0.974**로 작아짐. 생존/승리 판 혼입을 제거하지 않고
적의 후열 대상 확률이나 공격력을 올릴 근거는 아님.

  seed7·8판을 별도로 확인했음. 달 회랑100·태양 회랑200은 진행도 점수100/클리어100%,
  태양 회랑250은 진행도 점수82.31375/클리어25%임. 진행도 점수는 판별 진행도×100의 평균으로
  게임 공식 점수가 아님. 모두 진행도>0임. 엔진 변경이 없으므로 이 값은 진단 교정의 승률 개선 효과를 뜻하지 않음.
- `unsupported_allowlist.py --diff`: 추가/해소 키0개임. 담당 밖 키를 바꾸지 않았고,
  해소한 엔진 가정이 없어 `--write`로 다른 담당의 사유를 다시 쓰지 않았음.
- 수정 전 관련 시험2파일 통과했음. 중간 전체248파일 통과·실패0,
  COSMO_TABLES 미설정의 표 대조2건 건너뜀임. 마지막은 공용 잠금을 잡고 최신 T 경로를
  지정해 `run_tests.py --rebuild --strict`를 실행했으며 **249파일 통과·실패0·건너뜀0**임.
  워커·브라우저 e2e는 실행하지 않았음. 시험이 임시로 바꾼 이미지도 종료 뒤 원복됐음.

재현 예:

```powershell
python -X utf8 -I tools/ingame_check.py --only op4212 --bs-real --myinfo <비공개입력> --runs 200
python -X utf8 -I tools/op4212_audit.py --myinfo <비공개입력> --observations <비공개관찰.json> --output <저장소밖결과.json> --runs 200
python -X utf8 -I tests/op4212_audit_test.py --mutations
```

비공개 `role-private/op4212/`에 `baseline.json`, `audit_final.json`, `observations.json`,
`comparison_final.json`, `crosscheck.json`, 시험 로그를 보관했음. 공개 문서에는 계정 원값을 새로 싣지 않았음.

## 남은 일

과대평가 원인1건은 남았음. 특히 다음 두 증거가 없어서 스킬 단위 원인과 서버 보정을 구분하지 못했음.

1. 원본 영상의 스킬별 표시 피해·행동 순서·스킬 전 버프/보호막/HP를 판독해 같은 상태의
   `audit_final.json` 타격과 맞대기. 우선 1판 프레이 기본기 횟수, 3·5판 회복 시전 수,
   5판 최종 TURN·그웬 받은 피해를 확인해야 함.
2. 실제 작전 전투 입력의 양 팀 배율/적 최종 스탯을 확보할 수 있으면 NKM의 적용식과 대조하기.
   로컬 테스트 전투의1배나 관찰 피해에 맞춘 배율을 실제 서버 값으로 대체하지 않음.

첫 항목은 근거 부족, 둘째는 실제 서버 입력을 클라 표만으로 확정할 수 없는 범위임.
이번 조사만으로 엔진 과대평가가 해소됐다고 보고하지 않음.
