# 장비 던전 클라 직행 단계

## 입력·범위

`tools/build_foe_equip.py`가 클라 전투 행 → 번역된 탭·BattleName → 배치 스크립트 → 유닛·성장·스킬·SE·자동 대상·소환을 연결함. 출력 `data/foe_equip.json`은 기존 격전 조각과 같은 내부 인덱스 형식임. `build_foe.py`가 `foe_stages.json`으로 변환하며 화면 목록·추천은 기존 경로를 사용함. 엔진은 기존 격전·코스모 조각 뒤에 병합해 기존 인덱스를 보존함. 이미 있는 탭·단계와 그 보조 자료는 데이터북을 우선함.

빌드 26752678의 장비 행은 3×20개임. 실제 21·22단계 수치는 아직 없으며, 현재 배포 조각은 비어 있어 기존 단계와 화면 목록을 바꾸지 않음. 시험의 21·22단계는 사람이 만든 합성 입력이고 실제 패치 행이 아님.

근거는 비공개 static-data의 다음 파일임(설치본과 `decompiled/BUILD.md`의 빌드·DLL 10개 일치 확인).

- `tables/BATTLE_TEMPLET_NORMAL.json:173447,177357`: 20단계 전투 이름·레벨·권장 전투력·BattleMode·LimitTurn·배치 파일.
- `tables/BattleScript/JSON_NORMAL_BATTLE_EXPLORE_EQUIP3_020.json:5`: 웨이브·유닛·SpawnPosIndex·보스·시작 쿨·추가 스탯.
- `tables/UNIT_TEMPLET_BASE2.json:71574,72813,73433`: 소환 병졸·모티베이터·페르세스 20단계 정의. 연결된 `UNIT_STAT_TEMPLET2`·`STAT_ADD_PER_LEVEL2`에서 기본/성장 스탯과 명중·회피를 읽음.
- `decompiled/NKM.Templets/NKM.Templets.decompiled.cs:38436,38462`: 기본 스탯 배열은 0으로 초기화되고 없는 표 항목은 `GetInt32(..., 0)`으로 읽음. 생략된 명중·회피에도 같은 0을 적용함.
- `tables/SKILL_TEMPLET_2.json:12064` 이하와 연결된 `SKILL_LEVEL_GROUP_TEMPLET_*`·`SE_TEMPLET_SKILL_*`·`BUFF_TEMPLET`: 스킬·효과. 기존 격전 변환기의 검증된 효과 문법을 재사용함.
- `tables/BUFF_TEMPLET.json:6351,6471`: 강인도 회복·특정 버프 해제의 버프 자체 강제 적용. SE별 강제 적용과 구분하며 기존 공용 `buff_flags` 경로를 유지함.

## 대조 방법

`python -X utf8 -I tools/compare_foe_equip.py --out local/equip-compare.json`으로 같은 생성기를 `all_stages=True`로 돌리고 60단계를 대조함. 이름 키·레벨·권장 전투력·웨이브·턴 제한·승리 조건·배치·시작 쿨·소환, 유닛 스탯/속성/직업/등급/면역, 파싱된 액티브 스킬·효과 줄·자동 대상·강제 적용·자신 추가 발동을 비교함. 실제 전투 실행 결과 일치 시험과는 구분함.

데이터북의 아이콘 번호·상태 설명 카드 링크는 실행 입력이 아니므로 비교에서 제외함. 없는 쿨타임과 0은 같은 값으로 정규화함. 설명문 끝 공백, 면역 설명의 아이콘/문구는 실행값을 바꾸지 않음. 소환 AddStatData는 변형 스탯과 보조 자료에 함께 보존하며 엔진은 변형에서 한 번만 적용함.

빌드 26752678 대조는 **60단계·적 100체(소환 40체 포함)·액티브 스킬 260개·효과 줄 950개, 차이 0건**이었음. 첫 대조의 강제 적용 표시 80체 차이는 버프 자체 강제 적용과 SE별 표시를 중복 출력한 원인이었고 기존 공용 경로와 맞췄음. 소환 보조 자료 3단계 차이는 `AddStatData` 메타 누락이었으며 이를 보존하도록 고쳤음(변형에서 계산한 최종 스탯은 처음부터 같았음). 실제 신규 단계가 추가되면 `added`로 따로 보고하고 기존 단계 교집합만 대조함. 기존 단계가 클라에서 사라지면 실패로 셈.

## 회귀와 패치 후 확인

`tests/fixtures/equip_client_stages.json`은 세 탭 각각 20·21·22단계의 합성 전투 행, 배치·스탯·스킬·자동 대상 입력임. 실제 private 표 원문은 넣지 않았음. `tests/foe_equip_test.py`는 신규 6단계의 생성·기존 60단계 보존·중복 병합·엔진 로드·HTML 목록·추천을 확인함. 생성과 병합을 끄면 검증이 실패하는지도 검사함. 임시 출력은 `local/` 아래에만 생성함.

지원하지 않는 승리 조건·전투 보정·배치 필드·스킬 종류·효과 문법·대상 메타데이터는 예외로 중단하며 출력 파일은 완성한 뒤 원자적으로 교체함. 실제 패치에 새로운 패턴이 있으면 클라 조사·변환기 확장·시험이 필요함. 패치 후 재추출·생성·갱신·시험과 장비 등급 영향 확인은 [PORTING §4](PORTING.md#4-게임-업데이트가-있을-때)를 따름.

최종 장비 시험은 10/10 통과했고 미지원 관문 `--diff`의 변화는 없었음. 전체 시험은 280통과/1실패(환경 건너뜀 6건)임. 실패는 변경 전 main에서도 재현되는 길드 보관 시뮬 해시(CRLF 기준)와 Git 파일(LF)의 불일치로 인한 HTML 최신성 검사임. 길드 파일은 이번 작업 범위 밖이므로 수정하지 않았고, 재생성 시 길드 표가 빠지는 것을 확인한 뒤 기존 `index.html`을 유지했음.
