# 적 기믹 유형 발견 + 구원자 성향 매칭 검토

생성: `build_gimmicks.py` (실행 `python -X utf8 -I build_gimmicks.py`). 산출: `enemy_gimmicks.json`(유형 카탈로그+기믹 레코드), `multihit_traits.json`(구원자 다중 타수/단일 대형), `gimmick_counters.json`(구원자 태그, 유형별 선호/기피 규칙, 보스별 점수), `stage_gimmicks.json`(스테이지 키별 기믹 인덱스), `gimmick_residual.json`(유형 미매칭 문구 156종, 재검토용).
원칙: 확인 = 원문에 메커니즘이 명시됨. 추정 = 원문은 명확하나 "다중 타수에 불리한가"는 엔진 규칙(피격이 타수 단위인지 스킬 단위인지)을 알 수 없어 해석에 의존.

## 1. 방법 (키워드가 아니라 통독 -> 유형 제안)
- 적 스킬 원문 513종(숫자 정규화 후 고유)을 보스/정예/일반 모두 직접 읽고 묶어 유형 체계를 만들었다. 정규식은 읽은 결과를 옮긴 것이고, 안 걸린 문구는 residual 로 남긴다.
- residual 156종은 대부분 "단순 공격 + 일반 약화(출혈/방어력 감소 등)" 또는 "전투 시작 시 자기 버프"로, 일반 노이즈라 유형에서 제외했다(데이터에 약화 부여가 거의 모든 적에게 있어 변별력 없음).
- 적 스킬 상세는 `foe_raw.json`(u[].sk -> s[] d1) 문구가 전부이며, 스테이지 범위는 원본 g(콘텐츠>탭>스테이지>웨이브)를 직접 순회해 보스/정예/소환 적 등장 위치를 집계했다(foe_stages.json 과 동일 구조; 스테이지 고정효과 fx, 턴 제한 lt 도 같이 읽음).
- 정직한 한계: 적 스킬에 "N회 피격 후 발동" 류는 소수(8건)이고, 다단 히트를 직접 벌하는 문구(타수당 페널티)는 없다. 다중 타수가 불리해지는 것은 "피격 횟수 카운터/스택/턴당 첫 피격 후 감소" 같은 간접 기믹이다.

## 4. 구원자 성향 (56종 전부 reco key 매칭, 미매칭 0)
- 다중 타수 점수: 0=41, 1=4, 2=9, 3=2.
  - 3: 그웬 람파디스(추가 발동 3스킬), 티리아 집행자(추가 발동 2).
  - 2: 스마일 보이저/선샤인 캣(트리거 추가 공격 + 추가 발동), 샤를 하트 오브 모나스티르, 카넬리아 방랑자, 크리스텔 모렐, 로베르타 궤도 수색대(연타 문구+트리거), 오메가 보이저(메가 펀치 추가 발동), 클레어 플로리스, 로자리아 폴른 호크.
  - 1: 린 풍월당(추가 턴), 트리쉬 아셀루스(연속 참격 문구), 페이 방랑자, 프로페서M, 루나 화이트 펄(트리거 추가 공격)... (추가 턴만 있는 유닛은 점수 0)
- 스킬당 실제 히트 수는 원문에 "N회 공격"으로 거의 안 나온다(문구 검색 0건 수준). 따라서 점수는 "추가 발동/연쇄 피해/연속·연타 문구/트리거 추가 공격" 신호 누적으로, 추정이다.
- 단일 대형(SINGLE_BIG): 계수는 슬롯 표준값(기본 65 / 특수 단일 90 / 궁극 단일 115 / 광역 궁극 225)으로 전원이 같아 변별 불가. 대신 "단일 특수기/궁극기의 조건부 피해 증가 >= 30%(공통 +15% 제외), 다중 타수<=1, 광역 비중<=0.34"로 4명 표시: 벨 리스 캔들 스퀘어(입관 +30%), 에핀델 오를랑(오를랑의 매 +30%), 키라(침묵의 대가 +30%), 에핀델 블레싱 인 블룸(부케 토스 +150%). 이 4명 외에는 "단일 대형 성향 불명".
- 일반 태그(유형 규칙용): GAUGE_ALLY 31, DEBUFFER 24, SELF_SUSTAIN 17, SUPPORT_HEAVY 15, EXTRA_TURN 12, MULTIHIT 11, CD_REDUCE 9, BURST 9, CC_APPLY 8, SHIELD 8, HEAL 8, CLEANSE 7, AOE 5, DEF_PEN 5, BUFFER_DEP 4, SINGLE_BIG 4, RES_IMMUNE 4, GAUGE_DOWN 4, DISPEL 3, TAUNT 3, BREAK 2(강인도 피해 +N 문구; 'ab'는 슬롯 표준값이라 제외).

## 5. 검증: 대표 기믹 5개 (원문 판정) + 오탐
1. 공허감응자 규제 - "피격 후 이번 턴에 받는 피해량이 50% 감소... 한 턴에 2번 이상 피격 후 전체 연쇄 피해": TURN_HIT_REDUCTION 3 + HIT_COUNT_TRIGGER(턴당) -> **맞음**. 다단 히트가 직접 불리한 유일한 확정 기믹(첫 타 이후 타격이 반감).
2. 공허초월자 영면의 눈동자 - "전체 공격에 3회 피격 후 [드리운 영면] 발동... 강인도 격파 상태에서는 발생하지 않음": **맞음**. 전체 공격 3회가 카운트, 브레이크하면 발동 안 함(브레이크 딜러 선호 근거). 같은 보스 '칼날 같은 깃털'은 일반 3회 피격 + 달 속성 아니면 -30%.
3. 페르세스 방위 - "피격 후 단일 공격으로 받는 피해량 감소율 3%씩, 최대 10회": HIT_STACK_DEFENSE -> **맞음**(단일 연타일수록 단단해짐. 전체 공격은 해당 없음이 문구상 명시).
4. 복제체 마르실 일점 타격! - "피격 후 자신이 [보호막] 상태이면 [너트 돌리기]를 발동": SHIELD_GATED -> **맞음**(보호막 유지 시 피격마다 반격). 복제체 벨 리스 저주 반동(보호막 + 피격 시 출혈 3)도 같은 유형.
5. 공허습격자/매장자 사냥감 포착 - "[스킬 피해 무효]를 1회 발생": SKILL_NULLIFY -> 유형 **맞음**이나 영향 방향은 **추정**(무효 단위가 스킬인지 타수인지 문구에 없음).
오탐/주의(수정 반영 또는 남음):
- 수정함: 공허감응자 규제가 HIT_RETALIATION 으로 중복 분류, 처단자 "적의 생명력 50% 이하"가 HP_THRESHOLD 로 오분류 -> 규칙 수정.
- 남은 오분류: 번뇌의 숙고자 "[반격 증가] 부여"(피격 반응이 아니라 단순 반격 버프), 공허찬탈자 '찬탈의 잔재'(HP 구간 전환인데 HIT_RETALIATION 에도 걸림), 공허몰살자 물리적 말소(강화 반격 상태 조건).
- REACTIVE_TO_ATTACK_KIND 일부는 "자신을 제외한 아군이 단일 공격에 피격" (공허매장자/습격자 집단 보호 반응)으로 보스 본인이 아닌 부하 피격 반응.

## 6. 불확실한 판정 (추정)
- 피격 단위(타수 vs 스킬 단위): 모든 HIT_* 의 "다단 히트 불리"는 이 가정에 의존한다. '전체 공격에 피격', '단일 공격에 피격' 문구로 보아 스킬 단위 카운트일 가능성이 높고, 그렇다면 다단 히트(한 스킬 안의 여러 타)는 불리하지 않고 "추가 발동/연쇄 피해 같은 별도 이벤트"가 카운트를 늘린다. 즉 다중 타수 페널티의 실제 대상은 "스킬 사용 횟수(턴당 공격 횟수)"일 수 있다. 인게임 확인 필요(미검증).
- STEALTH/INVULN_GUARD/SKILL_NULLIFY: 용어 해설(gl)이 적 스킬에는 있으나 정의를 읽지 않음 -> 추정.
- 심각도(1~3)는 문구의 수치(N, %, 구간)로만 판단한 주관 점수. 가중치(유형 w)와 구원자 선호 규칙도 휴리스틱.
- 보스 규칙 점수(gimmick_counters.json)는 태그 희소성(IDF)으로 가중한 가산 점수라 상대 비교용 초안이다. 에핀델·아모라·프레이 등이 모든 보스에서 상위로 나오는 경향은 "대부분 유형에 선호 태그가 있어 태그가 많은 구원자가 유리"한 편향 때문일 수 있다.

## 7b. 기믹 유형별 역할 슬롯 / 스킬 구조 / 조합 점수 규칙 (엔진용: `gimmick_counters.json` 의 `slot_rules`, `combo_scoring`, `slot_pair_examples`)
슬롯 = 서로 다른 구원자가 채워야 하는 기능(태그 any). 조합 점수 = 0.5 x 개인점수 합 + 슬롯 충족 x 2.0 x (유형 가중 w x 심각도/2) + 슬롯 충족자끼리 연계가 있으면 +1.0 x 가중 + 조합 내 방향 연계 강도 x 0.5(추정 연계 절반).
연계 유형 번호는 synergy_pairs.json 기준: 1 부여->소비, 2 버프증폭, 3 생존연계, 4 쿨감·행동게이지->궁극/특수, 5 속성공유. 슬롯 태그: BREAK(강인도 피해 +N 문구, 2명뿐), DEF_PEN, BURST(궁극 계수>=250%), SINGLE_BIG(4명), DEALER(공격 스킬>=3), SELF_RELIANT(DEALER 이고 강화 의존 없음), 나머지는 4절 태그.
| 유형 | (1) 필요 슬롯 | (2) 선호 스킬 구조 | (3) 부적합 스킬 구조 | (4) 가감/연계 |
|---|---|---|---|---|
| HIT_COUNT_TRIGGER | 발동 차단(BREAK/CC/게이지 감소) + 단일 대형 폭딜 | 턴당 공격 횟수 적고 1타 큰 궁극 중심, 브레이크로 불발(공허초월자) | 추가 발동/연쇄/연타/트리거 추가 공격(MULTIHIT>=2); 전체 카운트형이면 광역 연타도 부적합, 단일 카운트형(오르트로스)은 광역 우회 | MULTIHIT 감점 -(1+0.5x(점수-2)); 슬롯 2 충족 +2 x w; 연계 4(쿨감->궁극) |
| TURN_HIT_REDUCTION | 1턴 1타 폭딜 | 궁극기 1회에 몰기 | 한 턴 다중 피격(추가 발동·트리거) | w=3 로 최대 가중 |
| HIT_STACK_OFFENSE / GAUGE_GAIN | 속공 폭딜 + 행동 억제 | 짧게 끝내는 버스트 + 게이지 감소/CC | 많이 때리며 오래 끄는 소모전 | 연계 4 |
| HIT_STACK_DEFENSE | 초반 폭딜 + 방어 관통 | 초반 몰아치기 | 저계수 연타 장기전 | |
| SHIELD_GEN / SHIELD_GATED | 보호막 파괴(BREAK/DEF_PEN) + 후속 폭딜 | 파괴 담당 1 + 폭딜 1 | 보호막 유지 중 저피해 연타, MULTIHIT(피격마다 반응), 보호막 가중 피해 보스에 보호막 부여형 | 연계 1/2; 예: 타냐->마르실/루나/클라리사(부여->소비 강도 3) |
| BUFF_STRIP / BUFF_STATE_PUNISH | 자립형 폭딜 + 클렌즈/재부여 | 강화 의존 낮은 딜 | BUFFER_DEP(강화 효과 개수 비례) | 연계 2; 예: 타냐->루나, 프레이->루나 |
| DEBUFF_SCALING | 클렌즈/면역 + 폭딜 | 약화 해제/면역 | 약화 다수 피격 | 연계 3; 예: 카르멘->페이 |
| DEBUFF_GATED_POWER | 디버프 부여 + 디버프 소비 폭딜 | 부여->소비 쌍 | 클렌즈 위주 | 연계 1; 예: 스칼렛->뮤리엘, 루그->세레스, 루나(화이트 펄)->나루 |
| SELF_BUFF_DEPENDENT | 강화 해제(DISPEL) + 폭딜 | 적 강화 해제 | 해제 수단 없음 | 연계 1; 예: 벨 리스->키라(침묵->피해 +30%), 스칼렛->나루 |
| ENRAGE_STACK(대부분의 보스) | 가속(게이지/쿨감/추가턴) + 폭딜 | 가속 담당이 폭딜의 궁극/특수를 앞당김 | 느린 누적형, 서포트 3명 이상 | 연계 4; 예: 카르멘->오메가/린/세레스 |
| SUMMON / LINKED_MINIONS | 광역 + 브레이커 | 부하 우선 정리 | 보스만 단일 연타 | |
| TARGET_PRIORITY / OPENER_BURST / PCT_HP_DAMAGE / HIT_RETALIATION | 보호·도발·힐 | 지정 대상을 받아냄/개전 방어 | 저내구 딜러가 지정 대상 | 연계 3(생존연계) |
| CC_APPLY / GAUGE_DENIAL / RESIST_IGNORE / HEAL_BLOCK | 클렌즈·면역/게이지 복구/보호막 | 저항 스탯 대신 해제·보호막 | 효과 저항 스탯 의존, 힐 의존 | |
| TOUGHNESS_IMMUNE_WINDOW / TOUGHNESS_BREAK_REACTIVE | 폭딜 + 브레이커 | 무효 구간 전 버스트/후 브레이크; 격파가 이득이면 부하 브레이크 | 격파 시 강해지는 보스(공허몰살자)에 브레이커 | |
| HP_THRESHOLD_PHASE / STEALTH / SKILL_NULLIFY | 구간 전 폭딜 / 광역 | 한 번에 구간 통과 / 은신 무관 광역 | 구간 근처 쪼개기, 단일 집중(추정) | STEALTH·NULLIFY 는 추정 |
| ELEMENT_RESIST / ELEMENT_BIAS_ATTACK | (슬롯 없음, 속성 param) | 웬디고=별, 공허초월자=달 | 그 외 속성 | 개인 점수에 +-1.5 |
데이터 한계: BREAK 태그 구원자가 2명뿐이라 "보호막 파괴 담당" 슬롯은 DEF_PEN(5명)으로 사실상 대체된다(보호막 직접 파괴 스킬 문구는 구원자 쪽에 없음 -> 슬롯 의미는 추정).

### 스테이지 키 / 엔진 읽기
- `stage_gimmicks.json`: 키 `content|tab|stage`(예 `cosmo|길레|길레 1단계`) -> `{boss_units:[{unit,boss,elite}], types:{유형코드:{sev,units,gids}}}` (기믹이 있는 3,596 스테이지; `gids` 는 `enemy_gimmicks.json` 의 레코드 id `G0000` 형식).
- `enemy_gimmicks.json` 의 각 기믹 레코드에 `gid`, `stage_keys`(최대 60개, 넘으면 `stage_keys_truncated`), `appearances`(콘텐츠/탭 요약)가 있다.
- 엔진 절차: 스테이지 키 -> `types` -> 유형 코드별 최대 심각도 tmap -> `slot_rules`/`type_rules` 로 개인 보정 + 후보 조합 `combo_scoring` 적용. 조합 함수는 `build_gimmicks.py` 의 `combo_score(members, tagmap, indiv, tmap, pairs)`/`best_combos` 참고(구원자 키는 savior_reco key).

## 8. 한계 / 미검증
- 모든 영향 방향은 문구 해석이며 인게임 미검증. 특히 피격 카운트 단위.
- 구원자 스킬 히트 수는 데이터에 없음: 계수는 슬롯 표준값이라 단일 대형도 직접 판별 불가(4명만 조건부 피해 증가로 표시).
- 속성/면역 해설(gl)의 [수호], [은신], [면역] 정의, 별의 도전 보정, 소환 적 세부 스킬은 읽지 않음.
- 유형 매칭은 정규식이라 문구가 달라지면 누락된다(residual 156종 중 일부는 유형으로 승격 가능).
- 산출은 partynavigator 폴더를 수정하지 않았고 모두 `temp\journeyhelper\work\party\` 안에 있다.
