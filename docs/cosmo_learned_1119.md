# 코스모 게이트 계정별 점수 학습 선별 — 2026-11-19

## 동작

2026-11-20부터 학습 선별을 기본으로 켰음. 화면 «계정별 점수 학습 선별»에서 끌 수 있으며 켜져 있으면 기존 빠른 탐색보다 우선함. 기본값 정본은 아래 설정 파일임. 전투력으로 보유 풀을 줄이지 않으며 기존 `maxPool`도 이 경로에서는 적용하지 않음. 육성된 보유 구원자와 역할 조건은 기존과 같음.

설정 정본은 `data/cosmo_raid.json`과 `tools/build_cosmo_raid.py`의 `SEARCH.learned`임. `S`는 표본 상한, `m`은 구원자별 표본 최소 수, `K`는 전역 예측 상위 후보, `M`은 구원자별 후보, `A`는 제외 집합 감사 크기임. `overlapStarts`·`overlapKeep`은 겹침 회피 탐색 수, `folds`·`epochs`·`ridge`는 회귀 비용, `minCorrelation`·`missThreshold`는 품질 복귀 문턱임. `maxScoreCombos`는 학습 순회 조합 상한이고 기존 `maxCombos`는 학습을 끈 경로의 상한임. 모든 값은 경험적 탐색 정책이며 게임 클라 규칙이 아님.

1. 균등 reservoir 표본과 구원자별 reservoir 예약분을 합쳐 보스별 표본을 구성함. 유효 조합이 충분하면 각 구원자가 최소 m회 포함됨. S가 인원×m보다 작으면 계산 전에 설정 오류로 막음.
2. 기존 첫 판·대표 난이도·실제 배치·리더로 평가함. 선택 지표(mean/top)에 대해 구원자·앞열/뒤열·리더의 효과와 역할/속성 쌍의 능형 회귀를 학습함. 전투력 합·quick 분류값은 특징에 넣지 않음. 배치 규칙 자체는 기존 전투력 순서와 같음.
3. 표본 순서를 고정한 교차검증의 Spearman 상관을 기록함. 전체 조합은 generator로 순회하고 크기가 제한된 힙만 보관함. 구원자마다 예측 상위 M을 합치고 여러 예측 삼중의 다른 두 팀 8명을 피하는 팀을 추가함. 두 팀조차 겹치면 한 팀을 피하는 두 번째 팀부터 전체 공간에서 찾음.
4. 후보 외 집합에서 균등 비복원 감사 표본을 뽑음. 실제 점수가 core의 통과 경계 이상인 비율이 문턱을 넘거나 상관이 낮거나 정의되지 않으면 해당 보스의 조합 수가 `maxCombos` 이하면 전수 확인함. 초과하면 `fallbackMultiplier` 배수만큼 K·M·A를 늘려 한 번 재선별하고 예측 확인 부족 안내를 결과에 표시함. 확대 후에도 품질 보장을 뜻하지 않으며 기존 정밀 후보 상한은 유지함. 완료한 표본·후보의 첫 판은 다시 돌리지 않음. 복귀 작업 객체는 512팀씩 만듦.
5. 기존 보충·정밀·삼중·난이도 자동·브레이크 최종 확인으로 연결함. 보충·정밀 단계에도 구원자별 실제 상위 M과 겹침 회피 후보를 유지함. 정밀 합집합이 상한을 넘으면 보장을 조용히 자르지 않고 오류를 표시함. 삼중 하나가 아니라 설정된 여러 삼중을 채울 때까지 상한 내 후보 확대를 시도함.

메모리 비용은 선별 중 표본·K·인원×M·겹침·A에 비례함. 전수 복귀 때는 완료 결과와 가벼운 조합 인덱스를 전수 보관하므로 메모리·시간이 다시 증가함. 시작 전 판 수는 후보 합집합 상한이며 실행 중 실제 중복 제거 수로 고침. 복귀 때 미완료 보스까지 포함해 단계 판 수를 늘림. 난이도 자동의 비교 시간은 기존처럼 별도 단계로 안내함.

## 계정 대조 CLI

```powershell
node tools/run_cosmo_search_cli.js --myinfo C:\private\myinfo.json --mode learned --metric top --level auto --workers 4 --output C:\private\learned.json
node tools/run_cosmo_search_cli.js --myinfo C:\private\myinfo.json --mode legacy --metric top --level auto --workers 4 --output C:\private\legacy.json
```

실제 브라우저 탐색 JS와 Python 전투 엔진을 연결함. `--python`으로 Python 실행 파일을 지정할 수 있음. `--seed`는 단계별 시드에 100배 오프셋을 더함. 자동 난이도가 기본이며 `--level N`으로 고정할 수 있음. `--metric mean`도 지원함. myinfo의 보유 브레이크 스킬을 읽고 지원되는 것과 미장착을 비교함. `--breaks` JSON 배열을 주면 명시적으로 대체함.

입력은 인자 경로에서 읽기만 함. 출력은 저장소 밖의 기존 디렉터리로 지정해야 하며 Windows 대소문자·심볼릭 링크를 확인함. 결과에는 3팀·앞열/뒤열·리더·브레이크·난이도·보스별 점수·합계와 상위 10개 후보(찾은 수가 적으면 그 수), 단계별 판 수·시간·감사 진단이 있음. 실계정으로 이 도구를 실행하지 않았음.

## 한계

- M은 구원자 포함과 대안의 보장이며 희귀한 4인 시너지나 전역 최적 삼중의 보장이 아님. 감사 비율은 첫 판 통과 경계 누락률이며 최고 삼중 누락 확률이 아님.
- 표본 1판의 top은 mean과 같은 값임. 다회 top의 꼬리 특성을 학습한다는 의미가 아니며 최종 다회 검증은 유지함.
- 예측 상관·감사는 같은 대표 난이도에서 평가함. 다른 난이도·브레이크에서만 강한 팀을 초기 단계에서 놓칠 수 있음.
- 네이티브 Python 측정 시간을 브라우저 Pyodide 시간으로 바꾸어 단정하지 않음. 실제 계정·다른 기기·장시간 브라우저 메모리는 미확인임.
