## 설계의 구체화

- 동료 풀 16명·대상별 후보 2팀·4판 예선·최대 48개 시나리오를 100판 재평가·전체 7,200판/120초로 정했음. 상한 밖 후보는 미평가로 남김. 동료 풀 제한 때문에 전역 최적은 아님.
- 치명 분기·치명 부옵 재분배는 표준 Lv200 세팅을 고정했음. 실제 계정마다 장비를 재최적화하면 비교할 목표도 달라지므로, 공통 build 정책이 만든 재현 가능한 목표로 선택했음.
- 보유 육성은 공명·스킬·여정·특수 잠재력 묶음이며, 장비는 별도 시나리오임. 항목별 임의 목표를 편집하는 UI는 넣지 않았음. 합성 API는 변경 필드 선택을 지원함.
- 수동 예선은 기존 탐색과 같이 오토임. 본선은 수동으로 비교하고 서순 탐색·재생까지 팀당 333판을 예산에서 차감함. 순위는 단위가 다른 점수를 더하지 않음.
- 기존 보유 최고는 반드시 독립 재평가 목록에 남김. 해당 결과가 제한 시간 안에 완료되지 않으면 개선폭을 비우고 「기준 재평가 미완료」로 표시함.

## 시험과 실측

- 기준선: `STARSAVIOR_STATIC=E:\AI_mk2\starsavior-static-data`, 일반 104개 통과/0 실패였음.
- 옵션을 끈 엔진: 기준 커밋의 `make_build()`를 메모리에서 읽어 현 코드와 비교했음. 57명 × none/light/standard = 171건 정확 일치했음. 골든 기대값은 변경하지 않았음.
- 생성 시험: 프리셋 UID 전원 수록, 6부위 +15·세트·부옵·잠재력 합, 잠재력 한 번만 가산, 최대 스킬·전투 어댑터 지원을 검사함. JS에서 normal/fixed200·원본 보존·출처·장비만 변경·누락 거부를 검사함.
- 탐색 시험: 대상별 최소 후보, quick/근사 양쪽 선발, 새 시드·동일 판 수, 더 좋은 보유 대조팀, 기존 최고 보존·기준 미완료, 음수 변화·미평가, 상한·취소·서명·shared 미저장을 검사함.
- 실제 브라우저 시험은 `tests/fixtures/myinfo_synthetic.json`만 계정 입력으로 사용함. 이 fixture의 의도적으로 빠진 전술 그룹 필드는 메모리에서 명시적인 0으로 채웠음. 제품 코드는 누락 값을 보충하지 않음.
- 기능 연결을 `growthMaybe=()=>{}`로 끊은 e2e 실행은 표 완료 조건에서 실패했음. 원복 후 같은 경로가 통과했음. 생성·서명·공유 저장 방지, 기존 보유 최고 탈락, 기준 재평가 미완료 비교 변형도 실패 감지를 확인했음.
- 최종 일반 시험은 106개 통과/0 실패임(`local/assumed-final-unit.log`). 마지막 화면 수정 뒤 해당 JS 시험과 실제 기능 e2e 3개도 다시 통과했음(`local/assumed-final-feature.log`).
- 브라우저 41개를 검증했음. 전체 회귀에서 공유 링크 시험만 옛 query 허용 목록 때문에 실패했고, ag/ae/ao를 포함한 계약으로 갱신한 뒤 해당 시험 전체를 다시 실행해 통과했음(`local/assumed-share-final.log`). 나머지 40개는 전체 실행에서 통과했음. 발견된 실패는 모두 해소했음.
- 중간 통합 실행의 `gim_avoid_test` 실패는 템플릿 CRLF 때문에 함수 추출이 안 된 것이었음. 템플릿을 LF로 원복한 뒤 위 일반 시험 106개를 다시 실행했음. 엔진 기대값·골든을 바꿔 맞추지 않았음.

## 남은 확인 범위

- 실계정·실게임 영상과 가정 편성의 정확도 대조는 하지 않았음. 표준 세팅·평균 부옵은 정책이며 실제 소유 장비·육성 비용을 뜻하지 않음.
- 보존된 구원자 1060의 성장/스킬 표는 기존 빌더의 이전 값 보존 경로를 따름. 현재 클라 표에 다시 존재하는지는 미확인임.
- 전체 시험의 `COSMO_TABLES`, 옆 journeyhelper 저장소가 필요한 두 검사는 환경 부재로 건너뜀. 비공개 static-data는 `64e4fad`를 읽기 전용으로 사용했음.
- 길방·코스모 실행 경로는 이번 범위에 넣지 않았음. HANDOFF 수정·푸시·quick 재보정·guild_sim 재계산·골든 쓰기를 하지 않았음.
- 시작 시 `git pull --ff-only`는 작업 브랜치 추적 대상이 없어 적용되지 않았음. 임의의 원격 브랜치를 병합하지 않았음.
