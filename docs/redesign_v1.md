# 재설계 v1 — 설계 (2026-10-20, 1단계 구현 완료)

## 확정 사항 (사용자 의견 + codex 설계 상담 반영)
- 사용자: 「주 목표는 특정 콘텐츠를 어떤 파티로 하면 깰 수 있는지」, 「장비·레벨·돌파·스킬 레벨이 변수 → **평균적인 상황일 때 이 파티로 깰만함** 정도면 된다」.
  → 네 변수를 **전투력 하나로 묶은 「육성 가정」**(평균 = 권장 전투력만큼 / 덜 키움 80% / 넉넉히 125%, 또는 내 파티 전투력 직접 입력)으로 처리. 결과는 「깰만함 / 빠듯함 / 어려움」 3단계.
  - 공식상 돌파는 단계와 무관하게 전투력 +6% 고정, 스킬 레벨은 1당 +1%, 레벨·장비는 공·생·방으로만 들어간다(데이터북 계산기 코드) → 전투력 하나로 묶어도 무리가 적다.
- codex 상담(종료코드 0) 반영:
  - ① 빠른 계산만으로 「해결」이라 하지 않는다 → **확률 엔진 결과(P4 사전 계산 3,655건)를 정답지로 계수를 맞추고 일치율을 화면에 표시**(반반 검증 94.8%).
  - ② 파티 합 전투력은 「평균 육성 추정」으로 표시. 구원자별 전투력 저장은 다음 단계.
  - ③ 쾌적 순서 = 깰만함 > 빠듯함 > 어려움 → 남는 생명력 → 처치 턴. 「필요 전투력」은 「권장의 약 N%」 추정치로 표시.
  - ④ 후보를 근사 상위 몇 팀으로 자르지 않고 **근사 후보 풀의 모든 4인 조합**(수천 개)을 빠른 계산으로 평가.
  - ⑤ 상단에 가정(전투력·권장 대비 %)·일치율을 고정 표시. 보유 서랍은 그대로.
  - ⑥ 이견: codex 는 「인게임 실측을 먼저」라고 했으나, 실측은 사용자만 할 수 있어 구현과 병행한다. 화면에 「모델 추정」을 명시.

## 1단계 구현 결과
- `tools/build_quick_data.py` → `data/quick.json`(800KB, **1.6초**): 구원자 기준 스탯·전투력·턴당 피해·꼬리표, 스테이지 3,686개 웨이브별 적 요약. 게임 업데이트 때 이것만 다시 돌리면 된다.
- `battlesim/quick.py`(기준 구현) = `quick.js`(화면) — 같은 입력 300건 결과 일치(`tests/quick_test.py`, 일부러 깨뜨려 실패 확인).
- `tools/calibrate_quick.py`: 계수 A(아군 피해)·B(적 피해)·H(회복)를 시뮬 결과에 맞춤 → 균형 정확도 0.945(반반 검증 0.948), 시뮬 클리어 맞힘 99.3%·실패 맞힘 89.7%, 「1등 팀」이 시뮬 최선 -10%p 이내 96.3%(240 스테이지).
- 화면: 파티마다 맨 위 「이 스테이지 추천(빠른 계산)」 1안 + 차선 2개, 아래 상세 = 1안. 보유를 몇 명으로 줄여도 추천이 뜬다(문제 ① 해소), 사전 계산 불필요(②), 0% 대신 「권장의 약 N%면 깸」·약점(③), 육성 가정(④).
- 한계: 계수는 Lv200·장비 없음 조건에서 맞췄다(다른 육성 수준은 전투력 비례 가정). 개별 구원자 사망·도발·쿨타임 타이밍은 안 본다(2단계 시뮬 몫). 시뮬 자체도 인게임 실측 전(×1.85·시작 쿨타임).
- 옛 사전 계산 화면은 `?pick=sim` 으로 계속 볼 수 있다(퇴역 전까지 시험용).

## ① 시뮬을 브라우저로 옮기나

**추천: 단계적 (다)→(가)** — 1단계는 빠른 계산만 브라우저로 내놓고, 2단계에 확률 엔진(`battlesim/mc.py`)을 JS 로 옮긴다.

- 빠른 계산(새로 만듦, JS 약 300줄 예상): 팀마다 「적 전체 HP 를 몇 턴에 깎나」 vs 「적 공격에 몇 턴 버티나」를 평균값으로 계산 → 클리어 여부·처치 턴·약점 한 줄. 후보 수백 팀도 1초 안.
- 시뮬 JS 이식(2단계): `mc.py`(약 1,800줄)의 실행부만 옮긴다. **스킬 문장 해석(파서)은 Python 에 남기고**, 해석 결과를 JSON 데이터 파일로 내보낸다 → 업데이트 때 할 일은 「데이터 파일 다시 만들기(수 초~수 분)」뿐, 1시간 사전 계산은 없어진다.
- 같은 결과 보장: 두 쪽에 **같은 난수 생성기**(시드 고정)를 넣어 「같은 입력 → 같은 숫자」 대조 시험. Python 은 기준 구현으로 계속 둔다.
- 화면이 멈추지 않게 시뮬은 **백그라운드 작업(Web Worker)** 에서, 팀당 100~200판.

| 안 | 좋은 점 | 나쁜 점 |
|---|---|---|
| **추천 (다)→(가)** | 1단계만으로 문제 ①②③이 바로 풀림, 이식은 검증된 기준과 대조하며 천천히 | 엔진이 두 벌(Python·JS) — 고칠 때 같이 고쳐야 함(대조 시험이 막아 줌) |
| (가) 처음부터 전부 이식 | 한 번에 완성 | 오래 걸리고, 그동안 화면 개선이 멈춤. 토큰 많이 씀 |
| (나) 빠른 계산만, 시뮬 폐기 | 가장 단순 | 쿨타임·도발·보스 우선 오토·쫄몹 남음 같은 「실제로 깨지나」 판단을 잃음 — 지금까지 만든 핵심 가치 포기 |
| (Pyodide 로 Python 그대로 실행) | 이식 불필요 | 첫 로딩 수십 MB·수 초, 모바일에서 느림 |

## ② 전투력 → 스탯 변환

**추천: 게임 전투력 공식을 그대로 쓰고, 「직업별 평균 세팅」의 스탯을 같은 비율로 늘리고 줄인다.**

1. 구원자마다 기준 상태(레벨 = 입력 또는 스테이지 레벨, 장비 = 직업별 평균 세팅 — `wip/p5-paused` 의 `builds.json` 재사용, 시험부터)를 만든다.
2. 그 상태의 전투력을 공식으로 계산(데이터북 계산기와 같은 식: 공·생·방 3방식 중 최대 × 속도·효과·잠재력 배율 × (1+0.06+스킬 레벨 합×0.01)). 이 식은 이미 문서에 확인돼 있다(`formulas_local.md` 209줄).
3. 입력 전투력 ÷ 기준 전투력 = 배율 k. **공격·생명·방어에 k 를 곱한다**(전투력이 이 셋에 비례하므로 정확히 맞아떨어진다). 속도·치명·적중은 평균 세팅 값 그대로.
4. 역보정: 파티 전투력 ÷ 권장 전투력 비율로 표(`power_penalty.json`)를 적용. 플래시 포인트는 미적용(공식 공지).
5. 입력이 없으면 「구원자마다 권장 전투력의 1/4 씩」으로 가정하고 화면에 「가정」이라고 표시.

| 안 | 좋은 점 | 나쁜 점 |
|---|---|---|
| **추천: 공식 역산 + 공·생·방 비례** | 게임 숫자와 맞음, 사용자가 인게임 전투력을 그대로 넣으면 됨 | 같은 전투력이라도 실제 세팅(치명 위주 등)과 다를 수 있음 → 「평균 세팅 가정」 표시 |
| 권장 전투력 대비 비율로 피해만 근사 | 아주 단순 | 버티기(HP·방어)와 화력이 같이 움직이지 않음, 「전투력 ○○면 깸」 숫자가 부정확 |
| 레벨·장비 직접 입력 | 가장 정확 | 입력이 너무 많음 — 「내 구원자」 서랍의 선택 입력으로만 둔다 |

확인 필요: **파티 전투력 = 4명 합인지**(역보정 비율 계산 기준). 데이터북 계산기 코드로 확인 후 진행.

## ③ 「쾌적」 기준

**추천: 순서대로 비교한다 — ① 클리어 가능 → ② 쓰러지는 아군 없음 → ③ 처치 턴이 짧음.** 오토 기준.

- 클리어 = 시뮬 클리어 확률 90% 이상(빠른 계산 단계에선 「깎는 턴 < 버티는 턴 × 0.8」 같은 여유 기준).
- 쓰러짐을 처치 턴보다 앞에 둔 이유: 오토로 편하게 깨려는 사용자에게 「한 명 쓰러지지만 빠름」보다 「안 쓰러지고 조금 느림」이 더 쾌적하다. 턴 제한 있는 콘텐츠(코스모 50턴)는 턴 제한을 ①에 포함.
- 아무 팀도 못 깨면: **필요 전투력이 가장 낮은 팀**을 1안으로, 「전투력 약 ○○면 깸」과 부족한 점 표시.
- 필요 전투력 = 전투력을 올려 가며 빠른 계산을 다시 해 처음 깨지는 값(이분 탐색, 계산 몇 번이면 됨).

| 안 | 나쁜 점 |
|---|---|
| 처치 턴 우선 | 위태로운 팀(힐러 없음)이 1위로 올라옴 |
| 점수 하나로 합치기(가중합) | 가중치가 또 임의값 — 지금 근사 점수의 문제를 반복 |

## ④ 기존 근사 점수와의 관계

**추천: 섞는다 — 근사 점수는 「후보 고르기」만, 순위는 새 계산.**

- 근사 점수(티어·상성·연계·기믹)로 보유 구원자 중 상위 약 50팀을 뽑고 → 빠른 계산으로 전부 평가 → 쾌적 기준으로 순위 → 상위 3~5팀만 시뮬.
- 근사 점수는 화면의 「추천 근거」에 참고로 남긴다.
- 후보에서 빠지는 좋은 팀이 없게, 근사 점수 외에 **역할 조합 보장**(딜러 2+·힐러/탱커 포함 팀 일부)을 후보에 추가.

| 안 | 나쁜 점 |
|---|---|
| 새 계산으로 완전 대체 | 보유가 많으면 조합 수가 수만 → 빠른 계산도 무거워짐, 연계·기믹 지식도 버림 |
| 근사 점수가 순위, 새 계산은 참고 | 지금 문제(근사 1위가 실제로 못 깸)가 그대로 |

## ⑤ 화면

**추천: 맨 위 「쾌적 1안 + 차선 2~3안」 카드, 지금의 상세는 접어 둔다.**

```
[스테이지 선택]  [내 전투력: ______ (비우면 권장 전투력 가정)]
┌ 쾌적 1안 ─────────────────────────────┐
│ 4명 배치(전열2/후열2) · 리더 · 브레이크 │
│ 클리어 ●● 95% · 약 6턴 · 쓰러짐 없음    │
│ 한 줄: 광역 2명이라 쫄몹 정리가 빠름     │
└──────────────────────────────────────┘
[차선 2안] [차선 3안]  (작은 카드, 「1안과 다른 점」 한 줄)
못 깰 때: 「전투력 약 128,000 이면 깸 · 힐러 없음 · 쫄몹이 오래 남음」
▸ 자세히 보기(접힘): 전투 전망 · 서순(수동) · 추천 근거 · 다른 후보
```
- 계산 순서가 화면에 보이게: 빠른 계산 결과가 먼저 뜨고, 시뮬이 끝나면 숫자가 갱신(「확인 중…」 표시).
- 「내 구원자」 서랍: 보유 체크 + (선택) 구원자별 레벨·전투력.
- 공식 UI 분위기 조정은 맨 마지막(브리프 5절).

## 진행 순서(확인 후)
1. 파티 전투력 합 여부 확인 + `wip/p5-paused` 평균 세팅 시험 → main 에 필요한 부분만.
2. 빠른 계산 JS + 전투력 변환 + 결과 카드 화면 → 브라우저 시험 → 커밋·푸시. (여기서 문제 ①②③④ 해소)
3. 시뮬 JS 이식(파서 결과 JSON 내보내기 → 실행부 이식 → 같은 난수 대조 시험 → Web Worker).
4. 사전 계산(`tools/build_sim_results.py`·`data/sim/`) 퇴역.
5. 화면 분위기 조정.

## 위험·미검증
- 결과를 크게 좌우하는 가정 2개(적 피해 ×1.85 적용 여부, 시작 쿨타임) — 여전히 인게임 1~2판 확인이 가장 값싸다(`calibration/README.md`).
- 빠른 계산은 평균값이라 「아슬아슬한 팀」을 잘못 판단할 수 있음 → 그래서 상위 팀은 시뮬로 다시 본다(2단계 전까지는 「빠른 계산 기준」 표시).
- 엔진 두 벌 유지 비용 → 대조 시험을 커밋 전 필수로.
