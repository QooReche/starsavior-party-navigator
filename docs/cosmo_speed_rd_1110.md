## 설계와 해석 범위

- 로컬 Windows PC·논리 코어 16·CPython 3.13.12에서 네이티브 작업자 8개로 측정했음. CPU affinity·클럭·다른 프로그램 부하는 고정하지 않았음. 전체 시험과 브라우저 측정은 네이티브 성능 측정 뒤에 순차 실행했음. 몇 % 차이를 환경 변동과 분리한 보장치로 해석하지 않음.
- 최종 추천은 현재 기본 순위인 **상위 20% 점수 평균(top)**으로 비교했음. 3보스·Step 3·난이도 6·브레이크 스킬 없음으로 고정했음. 자동 난이도·mean 모드·계정별 육성으로 일반화하지 않음.
- 공개 DB의 key 사전순 앞 30명과 54명을 골랐음. 점수를 관찰하기 전에 정한 풀임. 작은 풀은 앞열 역할 10명/딜러 20명·22,350조합, 큰 풀은 14명/40명·223,860조합임. 구원자별 standard 프리셋의 장비·잠재력 효과를 그대로 사용했음. 전투력은 `api.party_power`로 구하고, 실제 `GuildSearch.party`의 역할·전투력 순서를 적용한 뒤 standard 파티를 네이티브 엔진에 전달했음.
- 공격력×속도 대리는 standard UnitDef의 기본 stats를 사용했음. 전투력 대리에는 `party_power`의 잠재력 반영이 들어가지만, 능력치 대리가 화면에 불러온 계정의 최종 stats와 같은 분포라는 보장은 없음. 계정 입력으로 기본 채택할 근거로 확대하지 않음.
- 순위·동점·다양성·삼중 결합을 Python으로 재구현하지 않았음. `tools/bench_cosmo_search.js`가 실제 `cosmo_search.js`와 `GuildSearch.runPhase`를 실행하고, Worker 어댑터만 네이티브 Python으로 바꿨음. 판 수·선별 비율은 기존 설정 그대로임. 네이티브 분배 chunk는 100팀이고 브라우저 제품의 동적 chunk와 다름.
- 이 분배에서는 정밀 900팀이 9묶음이고 최종 30팀 이하는 1묶음이라 후반에 8워커를 모두 활용하지 못함. 단계별 wall-clock/판 수는 해당 분배의 처리량이지 전투 한 판의 순수 CPU 비용이 아님. 기준선과 실험에 같은 분배를 사용했고, 브라우저 전체 탐색 시간으로 외삽하지 않았음.
- 마스터 시드 R=5, 실제 단계 시드는 `100*r + [1,4,3,2]`임. 결과 배열이나 골든 해시를 다시 쓰지 않았음. R을 더 늘리는 대신 큰 풀 전수 5회와 팀당 gold 200판에 예산을 배분했음.
- gold는 모든 완료한 방법·시드의 보스별 정밀 후보 300팀과 최종 삼중 팀의 합집합을 독립 시드 900001로 팀당 200판 평가한 값임. 작은 풀 gold는 이 합집합 중 작은 풀 구원자로만 이루어진 팀으로 제한했음. **전역 최적해가 아니라 후보 합집합 안의 참값 근사**임.
- 후회값은 gold 최선 삼중 합에서 선택한 삼중의 gold 합을 뺀 값임. 마스터 시드 간 SD와 평균의 SE를 따로 계산함. gold 자체의 조건부 SE는 seed 900002·500회 paired bootstrap으로 계산하며, gold 최선 삼중을 선택한 불확실성까지 포함하는 구간은 아님.
- 1단계 통과 회수율은 첫 판 뒤 보충 판으로 넘어간 팀을 기준으로 함. 300팀 정밀 후보 회수율은 보조 지표로 별도 보관함. 1위 일치율·상위5 Jaccard·gold 최선 삼중의 구원자 놓침도 계산함.
- 재생 실행은 동일 입력·시드의 기존 전투 결과를 재사용하고 없는 팀만 실제로 계산함. 품질 검증에는 사용하지만 속도 판정에서는 제외함. 같은 마스터 시드의 재생/새 실행은 독립 표본 두 개로 세지 않음. 중단 후 재개한 실행도 전체 시간 판정에서 제외함.
- 감시 정확도는 같은 시드 기준선의 전수 첫 판을 이용해 제외 집합의 실제 놓침률과 표본 놓침률을 직접 대조함. gold 상위50의 초기 제외율도 따로 기록함. 첫 판 경계 초과율과 gold 상위50 제외율은 분모·목표가 다르므로 같은 확률로 취급하지 않음.
- 시간은 실제 단계 wall-clock과 JS 선별·결합을 포함한 전체 시간을 구분했음. raw JSON 압축·저장 시간은 계측 오버헤드로 따로 빼며, Python/JS 통신·워커 시작 비용은 포함함. 원자료는 무시되는 `local/` 아래에만 두었음.

## 실험 후보와 안전장치

`search.speed`에 value/legacy/alt를 두었음. `workerReuse`는 탐색 하나가 풀을 소유하고 단계마다 재사용함. 정상 종료·stale 반환·취소·오류·생성자 실패 때 풀을 닫음. `rngStreams`는 기존 엔진 옵션의 전달만 추가했고 기본은 false, 판 수는 20/40을 유지함.

대리 선별은 기본 꺼짐인 «빠른 탐색(실험)»임. 처음에는 r=.20/.35/.50/.70와 전투력·공격력×속도·방어력·생명력 합을 비교했음. 작은 풀 마스터 시드 0의 첫 판으로 r=.70, 벨그라스/카넬리아 전투력 합·티리아 공격력×속도 합, 놓침 문턱 .04를 정했음. 이 예비 시드는 튜닝 표본이므로 독립 검증으로 주장하지 않음. 나머지 시드와 큰 풀은 이 설정을 고정한 뒤 평가함.

대리 상위 팀에 구원자별 대리 상위 최소 3팀을 합치고, 제외 후보에서 전체 조합의 2%(최소 64팀)를 고정 난수로 비복원 추출해 함께 돌림. 제외 표본 중 core의 실제 첫 판 통과 경계 이상인 비율이 문턱을 넘거나 결과가 누락되면 해당 보스의 미평가 팀을 같은 첫 판 시드로 전수 실행함. 유효한 cosmo 결과가 있는 팀만 완료로 세며 누락 팀은 재평가함. 복귀 응답도 불완전하면 오류로 끝냄. 유효한 결과가 있는 팀은 중복 계산하지 않음. 경계 동점도 놓침으로 세며, 이후 기존 `pickPass`·`pickDiverse`를 유지함. 표본 감시는 희귀 시너지 놓침이 없다는 통계적 보장이 아님.

구원자 포함 보장은 유리한 4인 시너지 조합의 보장과 다름. 구원자 놓침 0만으로 품질 동등을 판정하지 않고, 후회값과 보스별 상위50 회수율 조건을 함께 적용함.

조합 수가 적어 첫 판 통과 수가 대리 core 크기 이상이거나 반감을 쓰지 않으면 대리 선별을 자동 생략하고 전수 확인함. 선택 상태는 유지하며 시작 전 안내와 결과 설명은 실제 전수 경로를 따름.

ETA 계획에는 대리 상위·구원자 보장·무작위 표본의 예상 판 수를 반영했음. 복귀 시 해당 단계 총량을 늘리고 이미 완료한 판·속도 표본은 유지함. 시작 전 문구에도 전수 복귀로 늘어날 수 있음을 표시함. 실험 선택은 새 페이지에서 꺼져 있으며, 일반 탐색 완료 때 이전 실험 표시를 지움. 속도 저장 키는 `pn.cosmo.speed.v2`로 바꿔 단계마다 부팅하던 옛 측정값을 읽지 않음. 단계 가중치는 측정 전의 근사이며 실행 중 실측으로 갱신함.

CRN·잘린 전투의 별도 파일럿은 작은 풀에서 보스마다 무작위 200팀과 기존 정밀 상위 40팀을 사용함. full/streams/독립 시드/streams 독립 시드/15행동/25행동을 각각 40판 비교함. 잘린 전투는 `max_turns`가 아니라 실제 행동 수 `turn_limit`을 줄였음. `max_turns`는 틱 시간 상한이므로 보고서의 제안을 그대로 대입하면 자원 축이 달라짐. 단축한 제한은 클리어 시 남은 턴 점수도 바꾸는 저충실도 실험임.

후반 예산 배분은 보스별 정밀 후보 상위 40팀에서 실제 균등20판, 5판→절반15판, 보정 없는 2표준오차 racing, 5판 뒤 OCBA 평균식 배분을 비교함. 앞 5판은 공통으로 실측하고 각 방법의 시간에 포함했음. 추가 판은 `run_offset=5`로 돌려 이전 판을 중복하지 않았고, 40판 참조의 같은 판 배열과 일치하는지 검사함. 독립40판 상위10과 회수율을 비교했음. 구원자 다양성 보장·순차검정 오류 보정이 없는 작은 집합 파일럿이고, 평균 기반 배분식을 상위20% 점수·삼중 결합의 정당한 선택 절차로 주장하지 않음.

브라우저는 Chromium/Pyodide 0.26.4에서 고정된 standard 전투 744판·4단계를 사용해 1/2/4/8워커를 각각 3회 비교함. 같은 반복 안에서 새 워커/재사용 순서를 번갈아 바꿈. HTTP 캐시를 한 번 예열하고, 관측용 worker 사본에서 준비 완료 시각과 WASM heap 용량만 추가 수집함. 이 작업량은 전체 탐색이 아니며, heap 용량은 프로세스 전체 메모리나 장시간 누수 검사와 다름. 전체 탐색 시간과 이 워커 곡선을 곱해 브라우저 전체 시간으로 주장하지 않음.
