## A. 2단계 길드 방어전 — A1 확정

- 1단계 파이프라인(가정 구원자 1명 고정 + 보유 동료 3명 재조합)에 길방 지표를 꽂음. `guild_search.runPhase` 는 실행기로 재사용.
- 지표는 기존 길방 정렬과 같게 **판별 점수 상위 20% 평균 → 상한 도달률 → 전체 평균**(`guild_search.js` `rankStats`). 점수는 판마다 `scoreFromProg`(단계·선택 효과 반영)로 계산 — 평균 진행도를 점수식에 넣지 않음(AGENTS «평균을 비선형 식에 넣지 말 것»).
- 예선 4판에서는 상위 20% 가 사실상 최고 한 판이라 선별 오차가 큼 → 예선은 평균·상한 도달률로 후보 다양성을 남기고, 별도 시드 100판으로 비교. 차이 구간은 Wilson 대신 판별 점수 **부트스트랩**.
- 조건: 사용자가 마지막으로 고른 단계, 보유 기준팀의 최선 지원을 양쪽에 고정. 결과 문구는 «현재 조건에서의 개선»으로 한정(팀마다 유효 지원이 다를 수 있음).
- 예산 7,200판·120초(기존 작업자 예산 공유). A2(가정 1명마다 기존 길방 탐색 전체 재실행)는 비용 대비 이득 불명 → 보류.

## B. 3단계 코스모 — B1 확정

- 보스별 후보 → 기존 `cosmo_search.js` `bestTriples`(보스별 `{keys, score}` 점수 내림차순, 비트마스크로 구원자 중복 금지) 재사용. 중복 제거 `finalJobs`, 순위 `finalRankBrk` 도 참고.
- 세 목록을 모두 «가정자 포함 팀»으로 만들면 결합 불가 → **가정자를 넣을 보스를 하나씩 고정**하고 나머지 두 보스는 보유 후보로 채운 세 경우를 합침. 가정자가 들어가며 밀려난 보유자는 다른 팀으로 이동 가능.
- 기준선: 기존 최고 삼중과 `pickDiverse` 다양한 보유 후보를 보존하고, 새로 발견한 보유 팀도 기준선에 반영(새 팀 발견만으로 이득이 생기지 않게 — 스타링크 추천과 같은 원칙). 보유자 육성 시 같은 구원자 키 유지.
- 지표: 3팀 합산 점수(기존 코스모 점수식) 대 보유만의 최선 삼중. 예산 12,000판·180초. B2(가정 1명마다 코스모 전체 탐색)는 보류.

## C. 보유 +15 장비 재분배 — C1 확정

- 범위: 내 정보의 **장착 장비만**(유닛별 6칸, 미장착 인벤토리는 입력에 없음). +15 만 이동, 나머지는 고정. 같은 부위끼리, 한 장비는 한 명만. 세트(12종, NeedParts 2 또는 4)는 `count // parts` 만큼 다시 계산.
- 장비 제약(비공개 표·클라 확인): 직업·구원자 전용 필드 **없음**(서버 제한은 미확인). 부위 6종(무기·장갑·갑옷·목걸이·반지·신발) — 배열 순서 말고 `myinfo_slots.json` 으로 판정. **길방에 쓴 장비·코스모 다른 보스에 고정된 장비는 이동 제한이 있음**(클라 안내 문구 `EQUIP_LOCK_DESC` 2종), 해제 시점·일반 잠금의 이동 제한은 미확인. 입력에 잠금·사용 이력·장비 개체 UID 가 없음 → 기본 표시는 «사용 이력이 없는 회차 기준 계획», 이동 제외 지정 기능 제공. 개체 식별은 계정 지문·원소유자·원래 칸.
- 탐색: 팀 구성은 먼저 고정(추천 팀)하고 장비만. 전수는 불가(4명 약 7×10^41) → 대상과 계정 전체 사이 **한 번 교환**(4명 1,308개·12명 3,636개)과 **2·4세트 묶음 이동**의 국소 탐색 + 빔.
- 1차 근사: `quick.js` 는 전투력 비율로 능력치를 늘리고 속도를 고정값으로 써서 장비 배분(속도·치명·적중)을 못 봄 → `final_stats` 로 세트 포함 실제 능력치를 다시 계산해 구원자별 공격 계수·치명 기대값·생존력·속도/적중 조건으로 후보를 남김. 현 장비 유지 후보도 보존, 짧은 시뮬 뒤 상위만 100판 재평가.
- 결과: 바꿀 장비 목록(어디서→어디로, 밀려난 장비의 목적지 포함) + 전후 확률/점수 차이. 팀 밖에서 빼 온 장비는 목록으로만 표시(다른 콘텐츠 영향은 합산하지 않음).
- 순서: 단일 팀 콘텐츠 → 코스모 3팀(팀 간 장비 중복 금지). C2(시뮬 없는 역할 가중치 할당)는 후보 생성용으로만, C3(여러 콘텐츠 동시 전역 재분배)는 합산 기준이 없어 보류. 예산 6,000판·120초.

- 공통 `search`에 지표 어댑터를 넣었음. 길방 `guildMetric`은 `GuildSearch.rankStats`와 같은 상위 20%→상한→평균 순서임. 판별 진행도마다 `scoreFromProg`를 적용함. 4판 예선은 평균·상한 후보를 번갈아 남기고 두 지표의 대표를 별도 시드 100판으로 재평가함. 시드 27011·1,000회 독립 재표집으로 상위 점수 차이의 95% 부트스트랩 구간을 계산함. 다중비교 보정은 하지 않았음.
- `growth_ui.js`의 `growthGuild`: 마지막 선택 단계·선택 효과에서 기존 보유 기준팀의 지원 후보를 100판씩 비교하고 최선 지원을 양쪽에 고정함. 지원 확인 비용도 7,200판·120초에 포함함. 협공 제외를 후보 생성과 실제 `via` 결과에 적용하고, 제외된 완료 판도 예산에서 차감함. 기준 재평가가 빠지면 개선폭을 만들지 않음.
- `growth_guide.js`의 `searchCosmo`·`cosmoTriples`: 가정자를 넣는 보스를 하나씩 고정한 세 경우를 기존 `CosmoSearch.bestTriples`로 결합함. 예선에서도 세 보스 모두 검사하도록 후보를 보스 순환으로 배치했음. 기존 최고 삼중, `pickDiverse` 후보, 새 보유 대조팀을 함께 보존함. 보유 육성은 원래 키를 유지하며 동일 구원자는 3팀에서 한 번만 사용함. 최종에 필요한 대조팀까지 함께 100판 비용을 예약하고, 재평가 보유 최선 삼중과 합산 점수를 비교함. 대조팀·기존 기준의 결과가 빠지면 개선폭을 비움.
- 코스모 예선은 전체 예산의 최대 45%이며, 예선 보유 목록은 보스별 `pickDiverse` 24팀과 기존 기준팀으로 결합함. 최종에는 보스별 다양한 6팀·최고 삼중·선발 시나리오의 팀과 대조팀을 중복 제거해 남김. 전체 상한은 12,000판·180초임. 동점 후보가 많을 때 결합 계산이 과도해지는 것을 막기 위한 제한 탐색임.
- `cosmo_search.js`는 본선 보유 후보를 세션 메모리에 반환함. `guild_search.js`의 `runPhase`에 옵션·원결과 콜백을 추가해 두 가이드 실행기로 재사용했음. 기존 기본 실행 옵션은 유지했음. 가이드는 공통 `SIMQ.busy` 잠금을 사용하고 동시에 최대 3작업자를 실행함. 시간 제한·취소 시 작업자를 종료함.
- `build_party_html.py`의 코스모 화면 자료에 공개 표의 보스 속성을 추가했음. 빠른 계산 표가 없는 보스도 올바른 속성 상성으로 동료 후보를 고름. 기록 콘텐츠 키는 화면 자료의 실제 시즌 ID를 사용함.
- `party_template.html`·`growth_ui.js`: 육성 옵션을 켠 길방 EX·코스모에서 보유 검색 완료 뒤 실행 버튼을 표시함. 기존 결과 영역에 전후 점수·지원/난이도·편성·차이 구간을 다크 카드로 표시하고 상세 설명은 접기 하나에 모았음. 항목별 비교·미평가도 접기 안에 남겼음. 모바일 가로 넘침을 검사했음.
- `growth.history`에는 지표·단위·조건·요약만 저장함. 판별 배열·합성 유닛·장비 원문은 저장하지 않음. 공유 모드는 메모리만 사용하며 기존 내 정보 삭제 연동을 유지했음. 엔진 파일은 수정하지 않았음.

### 설계의 구체화·차이

- 길방과 벨그라스에는 `quick.json` 전투 표가 없음. 다른 콘텐츠의 빠른 계산을 빌려 쓰지 않고 연계 근사와 실제 전투력 순으로 동료 후보를 남겼음. 티리아·카넬리아는 해당 보스 3단계의 기존 빠른 계산을 사용함. 최종 순위는 모두 실제 시뮬 결과로 정함.
- 코스모 가정 비교는 기존 최고 삼중의 보스별 난이도·브레이크를 고정함. 자동 난이도 선택 상태에서도 보유 검색에서 선택한 난이도를 사용함. 가정 후보마다 모든 난이도·브레이크를 다시 탐색하는 것은 이번 B1의 예산 밖으로 남겼음. 화면·기록에 실제 고정 조건을 표시함.
- 코스모 작업자 출력은 판별 점수가 아닌 점수 요약임. 기존 점수식을 그대로 재사용하며 코스모 차이 구간이나 통계적 «개선 확인»은 만들지 않았음. 합산 점수의 양수·음수 차이를 그대로 표시함.
- 기준 커밋과 다른 폴더 읽기 전용 조건을 유지하기 위해 두 저장소의 `git pull`은 하지 않았음. 커밋·푸시·HANDOFF 변경은 하지 않았음. 생성물은 `tools/run_tests.py --rebuild`로만 갱신했음.
