## A. 2단계 길드 방어전 — A1 확정

- 1단계 파이프라인(가정 구원자 1명 고정 + 보유 동료 3명 재조합)에 길방 지표를 꽂음. `guild_search.runPhase` 는 실행기로 재사용.
- 지표는 기존 길방 정렬과 같게 **판별 점수 상위 20% 평균 → 상한 도달률 → 전체 평균**(`guild_search.js` `rankStats`). 점수는 판마다 `scoreFromProg`(단계·선택 효과 반영)로 계산 — 평균 진행도를 점수식에 넣지 않음(AGENTS «평균을 비선형 식에 넣지 말 것»).
- 예선 4판에서는 상위 20% 가 사실상 최고 한 판이라 선별 오차가 큼 → 예선은 평균·상한 도달률로 후보 다양성을 남기고, 별도 시드 100판으로 비교. 차이 구간은 Wilson 대신 판별 점수 **부트스트랩**.
- 조건: 사용자가 마지막으로 고른 단계, 보유 기준팀의 최선 지원을 양쪽에 고정. 결과 문구는 «현재 조건에서의 개선»으로 한정(팀마다 유효 지원이 다를 수 있음).
- 예산 7,200판·120초(기존 작업자 예산 공유). A2(가정 1명마다 기존 길방 탐색 전체 재실행)는 비용 대비 이득 불명 → 보류.

## B. 3단계 코스모 — B1 확정

- 보스별 후보 → 기존 `cosmo_search.js` `bestTriples`(보스별 `{keys, score}` 점수 내림차순, 비트마스크로 구원자 중복 금지) 재사용. 중복 제거 `finalJobs`, 순위 `finalRankBrk` 도 참고.
- 세 목록을 모두 «가정자 포함 팀»으로 만들면 결합 불가 → **가정자를 넣을 보스를 하나씩 고정**하고 나머지 두 보스는 보유 후보로 채운 세 경우를 합침. 가정자가 들어가며 밀려난 보유자는 다른 팀으로 이동 가능.
- 기준선: 기존 최고 삼중과 `pickDiverse` 다양한 보유 후보를 보존하고, 새로 발견한 보유 팀도 기준선에 반영(새 팀 발견만으로 이득이 생기지 않게 — 스타링크 추천과 같은 원칙). 보유자 육성 시 같은 구원자 키 유지.
- 지표: 3팀 합산 점수(기존 코스모 점수식) 대 보유만의 최선 삼중. 예산 12,000판·180초. B2(가정 1명마다 코스모 전체 탐색)는 보류.

## C. 보유 +15 장비 재분배 — C1 확정

- 범위: 내 정보의 **장착 장비만**(유닛별 6칸, 미장착 인벤토리는 입력에 없음). +15 만 이동, 나머지는 고정. 같은 부위끼리, 한 장비는 한 명만. 세트(12종, NeedParts 2 또는 4)는 `count // parts` 만큼 다시 계산.
- 장비 제약(비공개 표·클라 확인): 직업·구원자 전용 필드 **없음**(서버 제한은 미확인). 부위 6종(무기·장갑·갑옷·목걸이·반지·신발) — 배열 순서 말고 `myinfo_slots.json` 으로 판정. **길방에 쓴 장비·코스모 다른 보스에 고정된 장비는 이동 제한이 있음**(클라 안내 문구 `EQUIP_LOCK_DESC` 2종), 해제 시점·일반 잠금의 이동 제한은 미확인. 입력에 잠금·사용 이력·장비 개체 UID 가 없음 → 기본 표시는 «사용 이력이 없는 회차 기준 계획», 이동 제외 지정 기능 제공. 개체 식별은 계정 지문·원소유자·원래 칸.
- 탐색: 팀 구성은 먼저 고정(추천 팀)하고 장비만. 전수는 불가(4명 약 7×10^41) → 대상과 계정 전체 사이 **한 번 교환**(4명 1,308개·12명 3,636개)과 **2·4세트 묶음 이동**의 국소 탐색 + 빔.
- 1차 근사: `quick.js` 는 전투력 비율로 능력치를 늘리고 속도를 고정값으로 써서 장비 배분(속도·치명·적중)을 못 봄 → `final_stats` 로 세트 포함 실제 능력치를 다시 계산해 구원자별 공격 계수·치명 기대값·생존력·속도/적중 조건으로 후보를 남김. 현 장비 유지 후보도 보존, 짧은 시뮬 뒤 상위만 100판 재평가.
- 결과: 바꿀 장비 목록(어디서→어디로, 밀려난 장비의 목적지 포함) + 전후 확률/점수 차이. 팀 밖에서 빼 온 장비는 목록으로만 표시(다른 콘텐츠 영향은 합산하지 않음).
- 순서: 단일 팀 콘텐츠 → 코스모 3팀(팀 간 장비 중복 금지). C2(시뮬 없는 역할 가중치 할당)는 후보 생성용으로만, C3(여러 콘텐츠 동시 전역 재분배)는 합산 기준이 없어 보류. 예산 6,000판·120초.
