# 2026-11-03 — 강제 협공 재확인

## 근거와 기본값

- 근거 코드는 비공개 static-data `decompiled/BUILD.md`의 Steam build **26314877**임. 아래 줄은 `decompiled/NKM/NKM.decompiled.cs` 기준임.
- `5230–5232`: ForceCrossAttack 효과를 받은 대상의 플래그를 켬.
- `15508–15514`, `15645–15667`: 자신 제외·아머브레이크·기본기 사용 불가·DisableCrossAttack을 검사한 강제 후보 중 균등 1명을 고름.
- `15515–15521`, `15606–15641`: 강제 후보가 없을 때 일반 후보 전원 확률 판정 후 성공자 중 균등 1명을 고름.
- `14857–14867`: 본행동의 기본기 뒤 한 번 처리함. `13569–13572`: 턴 종료에 플래그를 초기화함.
- `15495–15504`: 저장한 대상이 사망하면 후보 선정 전에 취소함. 독립 리뷰에서 빠진 경계를 찾아 `coop_dead_target=cancel`을 추가했음. 옛 동작은 `legacy/alt=retarget`으로 보존했음. 이 키는 MC 전용이 아닌 공통 opts이며 시험에서도 이를 확인함.
- `opts.forced_coop_target=random`을 새 기본으로 했음. `legacy=live_atk`, `alt=[live_atk,stat_atk]`로 옛 즉시 시전 경로를 보존했음. `random`은 강제 효과를 받은 후보 사이의 추첨을 뜻함.

## 효과 대상과 최종 후보

- 프로페서M은 행동 가능·협공 불가 없음·높은 공격력 조건으로 체크 버프를 먼저 주고, 체크 버프를 받은 대상에 강제 협공 효과를 줌. 표 근거는 [추가 점검](client_recheck_extra.md)의 두 단계 절에 기록했음.
- MC는 공개 자동 대상 표로 실제 효과 대상을 구하고, 해당 대상의 플래그를 저장하도록 했음. 본행동 뒤 유효 강제 후보를 추첨하며, 최종 후보가 없으면 일반 협공 판정을 계속함. 플래그는 턴 종료에 초기화함.
- 기대값 엔진도 효과 부여와 시전을 분리했음. 독립 후보 존재 확률마다 성공 집합별 1/N을 합산하고, 강제 후보가 없는 몫만 일반 협공에 넘김. 교수M 체크·강화·해제·강제 효과 4줄은 공개 자동 대상 표에 연결했음.
- 기대값 모델은 아군 HP·브레이크 상태기를 자체 구현하지 않음. 표현 가능한 사망·브레이크·행동 불가·쿨·스킬 종류·협공 불가 상태를 검사하며, 확률 상태의 상관과 효과 대상의 동률 슬롯순은 기존 근사로 남겼음. MC와 전체 전투가 같다는 뜻은 아님.

## 시험

- 강제 협공 시험 파일 11개 시험: MC의 복수 후보·6,000회 균등 분포·자신 제외·우선권·단일 자리·사용 불가 8경계·일반 후보 전원 판정·효과 대상 보존·시점·턴 종료·legacy·일반/강제 스위치 독립성 및 두 엔진의 단일 대상 사망 취소를 검사했음.
- 공개 표준 육성 `clo/달 회랑/FLOOR 100` 실제 전투에서 강제 협공 경로 4회, 진행도 1.0을 확인했음. 계정 자료를 쓰지 않았음.
- MC 고장 주입 4종(유효성 검사 무시·턴 초기화 제거·선정 제거·효과 대상 버리기)은 각각 assertion 실패 6/1/1/1건을 탐지했음. 메모리 패치를 해제하고 정상 소스로 다시 검사했음.
- 단일 대상 사망 취소를 제거한 변이는 MC·기대값에서 각각 assertion 실패 2건을 탐지했음. 일반 협공 후보 순서 시험의 실제 전투 감시는 사망으로 취소된 행동을 제외하도록 고쳤고, 새 기본 분기 22회·진행도 1.0을 확인했음.
- 기대값 전용 12개 시험은 성공 집합 전수 계산·분수 후보·일반 fallback·효과 대상과 최종 추첨 분리·실제 피해 경로·턴 초기화·legacy를 검사했음. 고장 주입 6종 모두 assertion 실패를 탐지하고 원복했음.
- `mc_cache_test`, `heal_burst_test`, `golden_check`는 강제 협공을 `live_atk`로 고정하여 기존 시험 목적을 유지했음. `rules_test`의 옛 shared/independent 비교도 대상 규칙을 `live_atk`로 고정했고 P1 골든은 당시 입력 `stat_atk`로 고정했음. 골든·해시 기대값은 바꾸지 않았음.
- 위 해시·P2 골든 입력은 `coop_dead_target=retarget`도 고정했음. P1은 legacy에서 같은 값을 읽음.
