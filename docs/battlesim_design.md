# 전투 시뮬레이터 확정 설계 (2026-10-20)

Claude 초안 → codex(gpt-6-astra)·Fable 독립 검토 → 합의안. 근거 자료: `docs/formulas_local.md`(로컬 데이터·데이터북 계산기 코드), `docs/formulas_web.md`(공식 공지·아카라이브·일본 공략, 패치 연표).

## 1. 확정 방향 — 「축소한 C안」
- **Python 패키지 `battlesim/` 로 분리**한다. 코어(전투 상태·이벤트 순서·난수) / 스타세이비어 모듈(데이터 로딩·공식·스킬 문장 파서·행동 정책) / 평가(지표·추천 연결)로 나눈다. `battlesim` 은 `party_reco` 를 import 하지 않는다.
- **별도 IR 컴파일러는 만들지 않는다.** 지금 파서가 만드는 `Line`(시점·트리거·조건·대상·효과)이 곧 중간 표현이다. 이를 JSON 으로 덤프(`unparsed` 목록 포함)해 검사·비교에 쓰고, 적 스킬 `ef` 도 같은 파서로 읽는다. 단 조건은 0.8/0.2 같은 가중치로 뭉개지 말고 `HP 비율 ≥ 50%` 처럼 원래 조건 그대로 보존한다(난수 굴림 엔진에서 실제로 판정).
- **엔진은 하나, 난수 굴림(확률) 방식**으로 바꾼다. 치명·적중·협공·대상 선택·피해 난수(0.95~1.05)를 실제로 굴리고 `seed`·`n_runs` 로 반복한다. 기대값은 반복 평균. 기대값 전용 엔진을 따로 유지하지 않는다(규칙 이중 구현 방지). 지금의 기대값 화력 지표는 전환 전까지 후보 선별용 근사로만 남긴다.
- **JS 포트는 하지 않는다**(실제로 쓸 도구가 생기면 그때). 웹은 계속 사전 계산 JSON 을 읽는다.
- 확률 엔진 결과는 「가정한 모델의 확률」이지 실전 정답이 아니다 — 실측 대조로 따로 검증한다.

## 2. 재사용 계약(다른 도구에서 쓰는 방법)
`simulate(party_spec, encounter_spec, options) -> result`, CLI 는 JSON 입력/출력.
- party_spec: `[{key, level, res, star, potentials[], gear{}, stats_override?}]` + leader. `stats_override`(콘텐츠 적용 후 스탯 직접 입력)로 장비·육성 계산기 없이도 검증 가능.
- encounter_spec: `{enemies: foe 참조 또는 명시 스탯+스킬, wave, turn_limit, stage_fx}`
- options: `{seed, n_runs, rules_profile, rules_override, nova_policy(auto/manual), timeline}`
- result: `{schema_version, outcome{clear_p, wipe_p, ttk_median, ttk_p10_p90}, per_unit{dmg_share, dmg_taken, heal, death_turn}, timeline?, assumptions_used[]}`
- 시간 개념 3가지를 구분한다: 시뮬 시간(틱) / 개체별 행동 횟수 / 게임 턴 카운터(턴 제한 비교용). 일반 행동·협공·반격·추가 발동·연쇄 피해를 구분해 기록한다.

## 3. 모르는 규칙 처리 — 가설 프로필 + 민감도
규칙 파일(`battlesim/rules/*.json`)엔 **불확실하거나 바뀌기 쉬운 수치만** 둔다(모든 상수를 외부화하지 않는다). 항목마다 `{value, grade(data/official/community/assumed), alt, note}`.
| 항목 | 기본값 | 대안(민감도) | 근거 |
|---|---|---|---|
| 적 대상 선택 | 전열 0.8 / 후열 0.2, 디펜더 가중 ×2, 도발·은신·수호 우선 적용 | 디펜더 ×1~×4 | 나무위키·아카(가중치 미상) |
| 적 스킬 선택 | 쿨 찬 궁 > 특 > 기본 | — | 가정, 실측 대상 |
| 강인도 피해 | 스킬 `ab` 만, 상성 유리 +1·불리 0 | 기본기 +1 | 데이터 + 외부 |
| 협공 확률 상한 | 0.30 (`stat.cap`) | 1.00 | 데이터 vs 왈츠 아세라 문구 충돌 |
| 노바 포스 | 팀 공용 풀 | 개인 | 정황 강함(공식 미명시) |
| 노바 버스트 사용 | 플레이 방식에 따름(오토 = 안 씀) | 사용 | 커뮤니티 |
| DoT 버프 반영 | 매 틱 현재 스탯(데이터북) | 시전 시점/버프 제외(아카 실측) | 충돌 |
- 근거 없는 확률로 가설들을 평균 내지 않는다. 추천 상위 파티에만 한 변수씩 민감도를 돌려 **순위가 뒤집히는 변수만** 「이 추천은 ○○ 가정에 기댐」으로 표시.
- 실제 전투의 무작위성(난수)과 규칙을 몰라서 생기는 불확실성은 섞지 않고 따로 보인다.

## 4. 추천과의 연결
- 생존은 가중합이 아니라 **관문**: 턴 제한 안 클리어 확률을 먼저 비교하고, 비슷할 때 처치 턴으로 비교한다(높은 화력이 전멸 위험을 상쇄하는 추천 방지).
- 1,001 조합 전부 시뮬은 불가 → 기존 근사 점수로 순위 → **상위 10팀만 재시뮬**(후보당 32~64회, 최종 후보 별도 시드 400회).
- 역할별 후보·무작위 후보 일부를 보존해 근사 오류(예: 힐러가 선별에서 탈락)를 막는다.
- 플레이어에게 보여 줄 것: ① 처치 턴(중앙값·범위) ② 클리어/전멸 확률 ③ 누가 몇 턴에 먼저 쓰러지나 ④ 피해 기여 % ⑤ 가정 의존 한 줄.

### 4-1. 오토/수동 (사용자 결정 2026-10-20)
- **기본은 오토 전투 기준**으로 시뮬·추천한다(오토 규칙: 쿨 찬 궁 > 특 > 기본, 노바 버스트 안 씀, 대상은 보호막+HP 가장 낮은 적 — 확인되는 대로 rules 에 반영).
- 화면에 **「오토 / 수동」 선택**을 둔다. 수동이면 `nova_policy=manual` 등 수동 정책으로 다시 계산.
- **수동일 때는 「스킬 순서 가이드(서순)」를 보여 준다**: 시뮬이 찾은 좋은 행동 순서를 턴별로(예: 1턴 아모라 특수기 → 그웬 기본기(협공 유도) → … , 노바 4개 모이면 ○○ 궁극기에 버스트). 방법: 오토 정책을 기준선으로 두고, 행동마다 후보 스킬·대상·노바 사용 여부를 바꿔 보는 탐색(빔/몬테카를로)으로 클리어 확률·처치 턴이 가장 좋은 순서를 고른다. 오토 대비 얼마나 나아지는지도 함께 표시(「수동 시 처치 턴 −1.3」). P4 이후 항목.

## 5. 회귀·검증
- P1(구조 분리)만 기존 결과와 **정확 일치**. P2 부터는 의도된 규칙 수정이므로 절대값이 아니라 **순위 안정성**(상위 팀 순위 상관) + 변경 사유 파일(`docs/sim_changes.md`)로 관리.
- 지원 파티·보스별 핵심 효과 체크리스트와 「실행 중 만난 미지원 효과 수」를 결과에 기록(해석률 96% 여도 빠진 4% 가 생존을 결정할 수 있음).
- 이벤트 한도 초과는 정상 결과로 돌려주지 않는다.

## 6. 실측 보정(사용자 수집)
- **코스모 게이트·플래시 포인트**에서만 한다(Lv200·공명10 고정이라 시뮬 조건과 겹침. 장비·여정 적용 여부는 재확인 필요). 10/22 패치 전 작전 보스 결과는 쓰지 않는다.
- 파일 `calibration/cases.jsonl`, 전투 1건 = 1줄: `{date, patch, stage, party[4], leader, potentials, auto, clear, clear_turn, deaths[{who,turn}], end_hp_pct[4], damage_shown?, notes}`. 목표는 절대값이 아니라 순위·사망 예측 적중.
- 규모: 스테이지 5개 × 파티 2~3개 ≈ 20건(보정 2/3, 검증 1/3).
- 미상 규칙 미니 실험(각 1~20회 관찰): 협공 빈도, 노바 공용 여부(1판이면 판정), 적 단일 공격 대상(20회 전/후열·디펜더 집계), 보스 브레이크까지 타수, DoT 공버프 유무. 가능하면 녹화 영상의 첫 5~10행동(시전자·대상·스킬·피해·HP/보호막·강인도)을 표로.

## 8. 의견이 갈렸던 점과 결론
- IR: codex「작은 의미 IR 을 P1 에」 / Fable「만들지 말고 Line 덤프」 → **Line 덤프 + 조건 원형 보존**(둘의 공통분모).
- 규칙 외부화: codex「전부 외부화는 과설계」 / Fable「rules.json + 등급」 → **불확실 항목만** 외부화.

- Claude 초안과 달라진 점: IR 컴파일러 불채택, 기대값·확률 이중 모드 불채택, 「확률 엔진 = 정본」 표현 철회, 절대값 골든 → 순위 골든(P2~), 생존은 관문, 보정은 고정 콘텐츠 한정, 보정·실측 시작을 P5 → P0/P3 로 앞당김.
