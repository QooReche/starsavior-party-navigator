# 전투 시뮬레이터 규칙 교정 기록 (P2, 2026-10-20)

P1(구조 분리) 결과를 기준으로, 게임 데이터·공식 공지로 확인된 규칙에 맞춰 엔진을 고쳤다. 고친 것마다 **스위치**로 만들어 하나씩 켜고 끄며 영향을 쟀다.
- 스위치 위치: `battlesim/rules/default.json` 의 `opts`. 항목마다 지금 값(`value`), 교정 전 값(`legacy`), 근거 등급(`grade`), 설명(`note`), 출처(`source`).
- 측정 도구: `tests/rank_check.py` (기준 = P1 골든 `tests/golden/sim_golden_p1.json`). 스위치 시험: `tests/rules_test.py`.
- 「교정 전」 값만 모아 돌리면 P1 결과와 **소수점까지 똑같이** 나온다(표 첫 줄). 즉 아래 차이는 모두 각 교정 때문에 생긴 것이다.

## 1. 한눈에 보기

### 1.1 표 읽는 법
- **지표 Spearman**: 구원자 64명의 화력 지표(단일·광역 평균) **순위**가 얼마나 그대로인지. 1.0 = 순위 완전 동일, 0.99 이상이면 대부분 그대로.
- **값 바뀐 구원자**: 지표 숫자가 조금이라도 바뀐 구원자 수.
- **아군피해증가 Spearman**: 「다른 아군 피해를 몇 % 올려 주나」 지표의 순위 유지 정도(서포터 평가에 쓰임).
- **150팀**: 무작위 4인 팀 150개의 10턴 총 피해. Spearman = 팀 순위 유지 정도, 상위20 겹침 = 상위 20팀이 몇 팀 그대로인가, 평균 = 총 피해 평균 변화.
- **처치 턴 바뀐 칸**: 대표 스테이지 5개(길레 1~3, 매니저 그레고리 Ⅰ·Ⅱ) × 10팀(4딜덱 + 무작위 9팀) = 50칸 중 처치 턴이 바뀐 칸.

## 2. 교정별 설명

### 2.1 협공은 아군 「기본기」 뒤에만 (`coop_trigger`: basic_only, 교정 전 any_attack) — 근거: 공식
- **무엇**: 협공 확률을 가진 구원자는 다른 아군이 공격할 때마다 확률만큼 기본기로 따라 때렸다. 이제 **다른 아군이 기본기를 썼을 때만** 따라 때린다. 추가 발동·협공·반격으로 나간 기본기 뒤에는 협공이 없다(원래도 없었음).
- **왜**: 2025-12-18 공식 가이드 정정(「스킬 사용 시」 → 「기본기 사용 시」), 2026-09-10 NOA 가이드.
- **영향**: 협공 확률을 가진 구원자는 지금 데이터에 **왈츠 아세라 한 명**이다. 지표 4,940 → 4,171(-15.6%), 64명 중 29위 → 39위. 왈츠 아세라가 든 팀은 총 피해 약 -7%, 처치 턴 0.1~1.5턴 늦어짐.
- **말이 되나**: 예. P1 보고서에서 「서포터인데 딜러급」으로 의심했던 이상치가 줄었다. 개인 지표의 파트너(더미)가 기본 3 : 특수 1 : 궁극 1 비율로 행동하므로 협공 기회가 약 60% 로 준 것과 맞다. 그래도 서포터 중엔 여전히 화력 1위(4,130; 다음은 세르팡 2,081)다 — 협공 확률 상한 30%(데이터) 때문이며, 왈츠 아세라 문구(최대 +100%)와 상한의 충돌은 남은 민감도 항목이다.

### 2.2 공격 1번에 협공은 1명만 (`coop_single`: true, 교정 전 false) — 근거: 공식
- **무엇**: 협공 확률이 있는 아군이 여럿이면 예전엔 전원이 각자 따라 때렸다. 이제 한 번의 공격에 1명만 한다. 기대값으로는 「확률이 높은 사람부터, 앞사람이 안 했을 때만」 계산한다(예: 30%·30% 두 명이면 0.30 + 0.21).
- **왜**: 2026-09-10 NOA 가이드 「한 번의 공격에 아군 중 1명만 협공」.
- **영향**: **지금은 0**. 협공 확률을 가진 구원자가 왈츠 아세라 하나뿐이라 겹칠 일이 없다(시험에서 두 명일 때 0.30/0.21 로 나뉘는 것은 확인). 협공 구원자가 추가되면 바로 효과가 난다.

### 2.3 노바 버스트: 오토는 쓰지 않음 (`nova_policy`: auto, 교정 전 manual) — 근거: 사용자 결정 + 커뮤니티
- **무엇**: 기본 시뮬을 **오토 전투 기준**으로 바꿨다. 오토는 노바 버스트를 쓰지 않으므로 노바 포스는 쌓이기만 하고 「피해 +15%」와 노바 버스트의 「○○ 사용 시」 효과(예: 행동 게이지 +20%)가 없다. `manual` 로 바꾸면 노바 4개가 모일 때 다음 공격 스킬에 버스트한다.
- **왜**: 사용자 결정(2026-10-20, 설계 4-1절: 기본 = 오토, 화면에서 오토/수동 선택), 아카 2026-10-14 「노바 버스트는 오토에서 자동 사용 안 됨」.
- **영향**: 47명이 0~3% 줄었다(10턴에 버스트가 1~2번이라 작다). 순위는 사실상 그대로(0.9995).

### 2.4 노바 포스는 파티 공용 (`nova_pool`: team, 교정 전 unit) — 근거: 정황(공식 미명시)
- **무엇**: 수동(manual)일 때 노바 포스를 개인이 아니라 파티 전체가 함께 모은다. 4개가 모이면 그다음 공격 스킬을 쓰는 구원자가 버스트한다(개인 지표의 더미 파트너는 버스트하지 않음).
- **왜**: 적 「아군의 노바 포스 -2」, 카르멘 「노바 포스 2 획득」, 브레이크 스킬 「노바 포스 +4」 등 문구가 모두 하나의 풀을 가리킨다. 실측 1판이면 확정 가능(설계 6절 미니 실험).
- **영향**: 오토(기본)에서는 버스트를 안 쓰므로 **기본 결과엔 영향 없음**. 수동 기준으로 재면 개인 지표 0명 변화(혼자서 모으는 건 같음), 팀은 평균 +0.3%(버스트가 더 자주 남), 4딜덱 그레고리 Ⅱ 처치 10.9 → 10.2턴.

### 2.5 효과 적중 판정 = 효과 적중 − 효과 저항 (`debuff_model`: hit_resist, 교정 전 constant 0.9) — 근거: 데이터
- **무엇**: {효과 적중 판정}이 붙은 약화(방어력 감소·지속 피해·행동 게이지 감소 등)의 성공률을 「90% 고정」에서 게임 공식으로 바꿨다: `성공률 = 시전자 효과 적중 − 대상 효과 저항 ± 상성 30%p`(0~100%로 자름; 절대 적중/절대 저항 규칙도 넣었으나 적 절대 저항이 전원 0 이라 위 식 그대로). 「대상마다 75% 판정」 같은 확률은 이전처럼 따로 곱한다.
  - 구원자 효과 적중: 스탯(기본 100%, 프로페서M 108% 등) + 효과 적중 버프(카르멘·크리스텔·할리 등) + 리디아 「이번 스킬 효과 적중」.
  - 적 효과 저항: 스테이지 시뮬은 적 데이터(`foe_stages.json` 의 `evade`; 이번에 `tools/build_foe.py` 가 치명·효과 적중·효과 저항·절대 저항·강인도도 내보내게 함). 세르팡·리디아·나루(개화)의 「효과 저항 감소」 약화도 반영.
  - **개인 지표의 기준 적 효과 저항 = 60%**(가정): 대표 스테이지 5곳 보스(길레 20/40/60%, 그레고리 80/80%)의 중앙값. 다른 콘텐츠 보스 중앙값도 40~80%(작전 70%, 코스모 40%).
- **왜**: 데이터북 계산기 `calcHit`(게임 파일 기준), 공식 2026-05-21 「코스모 보스 절대 저항 삭제」.
- **영향**: 약화에 화력을 기대는 구원자가 내려갔다. 유미나 -18.6%(출혈 성공률 90% → 40%; 2위 → 5위), 세르팡 -13.1%, 바니 스칼렛(개화) -8.7%, 루그 -8.5%. 방어력 감소를 거는 서포트형(로자리아·스마일·페트라·루그)의 「아군 피해 증가」가 1.4~2.5%p 줄었다. 4딜덱은 약화에 기대지 않아 그대로.
- **말이 되나**: 예. 커뮤니티의 「디버퍼는 효과 적중 140%+ 필요」, 「회랑 행동 방해덱은 적중 180%」 같은 말과 같은 방향이다(장비 없는 Lv200 기준이라 적중 100%뿐). 단 장비로 효과 적중을 올리면 이 구원자들은 회복한다 — 지금 지표는 「적중 투자 없음」 기준.

### 2.6 프로페서M 강제 협공 대상 = 그 순간 공격력 1위 (`forced_coop_target`: live_atk, 교정 전 stat_atk) — 근거: 커뮤니티 관찰
- **무엇**: 프로페서M 기본기 뒤 「자신 제외 공격력 1위 아군」에게 협공시키는 대상을, 버프 없는 스탯 공격력이 아니라 **버프 포함 현재 공격력**으로 고른다.
- **왜**: 아카 2026-10-16 「AX 풀릴 때마다 페이가 프M 협공, AX 쌓여 아모라가 세지면 아모라」(관찰).
- **영향**: 개인 지표 변화 0(더미 파트너는 버프가 없음). 팀은 일부만 ±10% 안팎(공격력 버프를 주고받는 팀). 4딜덱(각인 0)은 대상이 계속 페이라 그대로.
  - 4딜덱에서 아모라 각인만 올렸을 때 강제 협공 횟수(10턴):

    | 아모라 각인 | 교정 전(스탯 기준) | 현재 공격력 기준 | 새 기본값 전부 |
    |---|---|---|---|
    | 0~1 | 페이 14회 (팀 420k/422k) | 페이 14회 (같음) | 페이 14회 (426k/428k) |
    | 2~5 | 아모라 14회 (475k~485k) | 페이 4회 + 아모라 10회 (465k~474k) | 페이 3회 + 아모라 11회 (473k~483k) |
  - P1 보고서의 「아모라 각인 2부터 협공 대상이 아모라로 바뀐다」가, 이제는 「버프가 풀리는 순간엔 페이로 돌아간다」로 바뀌어 커뮤니티 관찰(번갈아 감)과 같은 모습이 됐다.

### 2.7 지속 피해(DoT)는 매 틱 현재 스탯으로 (`dot_snapshot`: live, 교정 전 on_apply) — 근거: 데이터(충돌 있음)
- **무엇**: 연소·출혈·빙결·중독 피해를 「걸 때 값 고정」에서 「매 틱 시전자의 현재 공격력·피해 증가로 다시 계산」으로.
- **왜**: 데이터북 「매 턴 시전자 현재 스탯으로 재계산」(게임 파일 기준, 2026-10).
- **충돌**: 아카 실측(2026-02-19)은 「DoT 에 공격력 버프가 적용 안 됨」 — 데이터북과 반대. 데이터북(최신·게임 파일)을 채택했지만 실측 대상(설계 6절 「DoT 공버프 유무」)이다. `on_apply` 도 버프를 「걸 때 값」으로 넣으므로 실측과 완전히 같은 대안은 아니다.
- **영향**: 작음(4명 변화, 최대 유미나 -1.7%: 걸 때 붙어 있던 일시 버프가 틱 시점엔 빠짐). 순위 영향 없음.

### 2.8 장비 반영 순서 (`gear_order`: databook, 교정 전 legacy) — 근거: 데이터
- **무엇**: 장비 확장 훅(`calc_stats(gear=...)`)의 계산 순서를 게임 공식으로: `최종 = 버림(((기본+레벨) × (1+공명%) + 공명 정수) × (1 + 각인% + 장비%) + 장비 정수)`. 교정 전에는 장비 %를 따로 받지 않고(전투 중 `gear_atkp` 로 버프와 함께 곱함) 버림 뒤에 정수를 더했다. 장비 효과 적중·치명 정수도 상한 적용 전에 더한다.
- **영향**: **없음(증명)** — 지금 지표·파티·스테이지 어디서도 장비를 넣지 않는다. 표의 「골든 재현: 예」가 그 증거이고, 장비가 없을 때 두 방식이 같은 값을 내는 것과 장비 공격력 +300·공격력 +10% 를 넣으면 달라지는 것(3,397 → 3,707)을 시험으로 확인했다.

### 2.9 감소 합과 상한 50%, 브레이크 -15%p (`dmg_reduction`: sum_cap, 교정 전 none) — 근거: 데이터
- **무엇**: 피해식 `× (1 + 증가 합 − 감소 합)` 에서 감소 합을 만들고 상한 50% 를 걸었다. 브레이크는 「증가 합 +15%」가 아니라 「감소 합 −15%p」로 들어간다(감소가 없으면 결과는 같음).
  - 지금 감소 합에 실제로 들어가는 것은 **구원자가 적에게 거는 「받는 피해 증가」 약화**뿐이다: 루나 「속박」(전체 공격으로 받는 피해 +20%), 프로페서M 「표적 각인」(특수기로 받는 피해 +20%). 교정 전엔 이 두 약화가 아예 무시됐다.
  - 적 자신의 피해 감소 기믹(「끝없는 장막」 등)·스테이지 효과(받는 피해 −15/30%)는 적 행동·패시브 모델(P3)이 없어서 **아직 0** 이다 — 상한 50% 가 실제로 걸리는 경우도 그때부터.
- **영향**: 프로페서M +5.1%(아군 특수기도 같이 강해져 「아군 피해 증가」 +2.2%p), 루나 +1.9%. 프로페서M 이 든 팀 최대 +4.7%. 4딜덱 길레 3단계 29.3 → 28.8턴, 그레고리 Ⅱ 10.9 → 10.2턴.

### 2.10 강제 협공도 「공격 1번에 협공 1명」 자리를 쓴다 (`forced_coop_slot`: shared, 교정 전 independent) — 근거: 공식 + codex 2차 검토
- **결함**: 프로페서M 기본기 → 페이 강제 협공(가중 1.0) 뒤에도 같은 공격에 왈츠 아세라 일반 협공 0.3 이 또 붙었다. 또 프로페서M 기본기가 협공·추가 발동으로 나가면 그 기본기에서 페이 강제 협공이 다시 일어났다(협공이 연쇄됨).
- **고친 규칙**: 강제 협공이 이 공격의 협공 1명 자리를 먼저 차지한다(기대값: 일반 협공 후보는 남은 1 − 강제 협공 몫만 나눠 가짐). 추가 발동·협공·강제 협공으로 나간 기본기에서는 강제 협공이 일어나지 않는다(공식: 「반격·협공에는 협공 없음」).
- **영향**: 측정 묶음(150팀·스테이지 10팀)에는 프로페서M 과 협공 확률 구원자가 같이 든 팀, 프로페서M 기본기가 추가 시전되는 팀이 없어 0. 직접 잰 팀 프로페서M·그웬·페이·왈츠 아세라는 10턴 411,282 → 375,944(-8.6%, 그웬 131k → 110k·왈츠 아세라 46k → 35k), 길레 3단계 29.8 → 32.1턴. 4딜덱은 그대로(426,438).

### 2.11 실패한 약화 시도는 상태를 바꾸지 않는다, 지속 피해는 시전자별 (`debuff_state`: per_caster, 교정 전 overwrite) — 근거: 모델 정합성 + codex 2차 검토
- **결함**: 이미 걸린 약화에 다시 걸면 성공 가중치와 상관없이 지속 턴·시전자·계수를 덮어썼다. 예: 스마일 연소 0.52 중첩·1턴 위에 크리스텔 연소(성공 0)를 시도하면 중첩은 그대로인데 지속이 2턴, 시전자가 크리스텔로 바뀌어 지속 피해가 크리스텔 스탯으로 계산됐다.
- **고친 규칙**(기대값 모델에서 택한 규칙): ① 성공 가중치 0 이면 아무것도 안 바꾼다. ② 지속 피해는 시전자별 몫(중첩·지속 턴·계수)을 따로 두고 틱 피해도 각자에게 준다(전체 중첩 상한은 합에 적용). ③ 이미 있는 약화의 지속 턴 갱신은 성공 가중치가 0.5 이상일 때만(「성공할 가능성이 더 높을 때」). 지속 턴을 확률만큼 늘리면 남은 중첩이 통째로 오래 남아 과대가 되기 때문.
- **영향**: 작다. 개인 지표 0명(시전자가 한 명뿐), 150팀 평균 -0.15%, 지속 피해 구원자가 둘 이상인 팀만 최대 -5%(예: 바니 스칼렛 개화·카넬리아·뮤리엘·화이트펄 루나 -5.1%).

### 2.12 적 행동 게이지 감소의 기대값 (`gauge_expect`: exact, 교정 전 linear) — 근거: 기대값 정의 + codex 2차 검토(교정 전부터 있던 오류)
- **결함**: 성공률 q 인 게이지 감소를 `clamp(게이지 − q × 감소량)` 으로 처리해 0 경계에서 틀렸다. 예: 게이지 5%, −25%p, q 0.4 → 0 (맞는 기대값은 0.4 × 0 + 0.6 × 5% = 3%).
- **고친 규칙**: 효과 적중 판정 성공률 q 부분만 `q × clamp(게이지 + 변화) + (1 − q) × 게이지`. 조건·시전 가중치(예: 「냉각 1~5중첩」 줄처럼 서로 배타적인 갈래)와 아군 쪽 게이지는 선형 그대로 — 배타적인 갈래를 하나씩 기대값으로 적용하면 오히려 더 틀린다(세레스 자기 게이지 +70/+105%p 갈래에서 확인).
- **영향**: 거의 0(150팀 평균 -0.01%, 세레스 팀 최대 -0.4%).

### 2.13 지표 설명이 실제 쓴 옵션을 따른다(비차단)
- `build_index(opts=...)` 로 옵션을 바꿔도 결과의 설명(기준 적 방어·저항, 오토/수동)과 `_meta` 가 기본값을 적던 것을 실제 쓴 옵션으로 고침. 수치 영향 없음.

## 6. 다시 재는 법
```
python -X utf8 -I tests/rank_check.py --matrix --golden tests/golden/sim_golden_p1.json --md 표.md   # 이 문서 1.2 표
python -X utf8 -I tests/rank_check.py --base legacy --rules-override "{\"debuff_model\": \"hit_resist\"}" --golden tests/golden/sim_golden_p1.json
python -X utf8 -I tests/rank_check.py --rules-override "{\"enemy_resist\": 0.2}"     # 새 골든 대비 민감도(예: 기준 적 저항 20%)
python -X utf8 -I tests/rules_test.py
```
골든: `tests/golden/sim_golden.json` = P2 새 기본값(이 문서 기록 뒤 저장), `tests/golden/sim_golden_p1.json` = P1(교정 전) 보관본.
