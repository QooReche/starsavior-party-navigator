## 실행 계약

`stage_reco_check.py collect --learned`는 풀 안 팀뿐 아니라 콘텐츠 제한을 통과한 보유 전원 후보·프로필·브레이크·화면 함수 원문을 저장함. `learned_reco_measure.js`는 그 함수와 `cosmo_learned.js`의 sample/train/select/auditSample/audit, `recommend_pipeline.js`를 호출함. Python은 전투 전송·계측·통계만 담당함.

- 특징은 실제 `simParty` 엔진 순서의 구원자·앞뒤열·리더, 역할/속성 쌍, `teamBreak` 선택임. 전투력·quick 점수는 회귀 특징에서 제외함.
- 실제 1판 클리어 팀은 표본·감사에서도 보존해서 `scrCmp`로 승격 경쟁함. K는 `sc.fullN`, 예선은 `scrPrior`·`scrLegOpt`를 통한 1→8→32판 이어쓰기임.
- 본선 100판, 목표 미달 시 3→6→9팀 확장, 24가지 자리·리더 비교와 본선 재확인·되돌림은 화면 함수를 사용함. 최종 `quickRows`의 1위를 고정함.
- 복귀 시 원래 풀·빠른 계산 동점 순서·시드·승격 수를 복구함. 학습 판을 F에 재사용하지 않으며 학습 비용+F 비용임.
- F·A·C 모두 같은 수집 입력을 사용함. 브라우저는 실제 페이지의 `directRun('reco')` → `recoEnsure`부터 최종 1위 확정·그리기까지 잼(`learned_reco_browser.js`). 실제 공용 작업자·진행 표시·후보 확장·자리 비교를 사용하며 A·C의 선별만 측정용으로 주입함. 초기 페이지 열기·계정/스테이지 선택·독립 평가는 별도임. 선별에서 들어온 풀 밖 팀은 완료 직후 화면 재그리기에서도 유지하고, 재그리기가 확정 1위를 바꾸면 실패함. 제품 파일은 수정하지 않았음.

네이티브 시간은 수집된 후보·함수로 시작하는 탐색 시간이며 초기 빠른 계산 수집 시간은 포함하지 않음. 채택 조건의 시간은 실제 브라우저 전체 시간을 사용함. 브라우저는 매 실행 새 프로세스·캐시 없는 전투 작업자 8개를 쓰고 F→A→C 순서로 순차 측정함. 시간 자체의 신뢰구간은 계산하지 않았음.

## 실행 환경 대조 (앞 F·A·C 측정)

Windows, Ryzen 7 5700X(8코어/16스레드), 물리 메모리 약 32GiB, Node 24.14.0에서 측정함. 네이티브 계측·통계는 Python 3.13.12, 전투 작업자는 아래 32비트 Python이며 네이티브·브라우저 모두 작업자 8개임. 환경 원문은 `local/learned_reco/environment.json`에 둠.

64비트 CPython 예비 실행은 Pyodide와 판별 결과가 달랐음. `battlesim/mc.py:1336`의 `hash(st[:8])`가 행동 우선순위 난수 시드를 만들며, 정수 튜플 해시는 32/64비트에서 다름. 엔진 소스·옵션은 바꾸지 않고 본 네이티브 작업자를 32비트 CPython 3.12.1로 맞췄음. 같은 팀 독립 400판의 raw 문자열이 브라우저와 일치함. 64비트 예비 결과는 본 비교에서 제외함.

실행 파일은 [Python 공식 3.12.1 배포](https://www.python.org/downloads/release/python-3121/)의 Windows embeddable package (32-bit)를 `local/learned_reco/python32/`에 풀어 사용함. 시스템 설치·설정은 변경하지 않았음. Python 해시의 플랫폼 크기 차이는 [Python 데이터 모델 문서](https://docs.python.org/3/reference/datamodel.html#object.__hash__) 참조.

## 지정 표준 대상의 전제 확인

현재 main의 표준 육성 38-36은 tight 8팀, 31-36 재점화 3은 tight 5팀이며 태양 FLOOR 250도 safe/tight 팀이 있음. 따라서 세 곳은 `scrFullKeys`가 null이고 비교 제외임. 과거 bench의 «전원 못 깸»을 현재 사실로 옮기지 않았음. 추가 대상은 같은 수집 함수로 확인한 뒤 기록함.

추가 탐침에서도 작전 주요 스테이지 105곳·성간 회랑 119곳·달 회랑 99곳·태양 회랑 99곳, 합계 422곳 모두 전원 hard가 아니었음. 별 회랑 45곳도 충족 대상을 찾지 못해 탐침을 종료했음(총 467곳). `local/learned_reco/discovered/probe.json`에 실제 확인 범위·탈락 사유를 보존함. 육성 배수를 낮추거나 F 발동을 강제하지 않았으며, 표준 육성에서의 품질·시간 비교는 미측정임.

## 재현 (앞 F·A·C 측정)

수집은 Playwright Python, 네이티브 계측·분석은 psutil/numpy가 있는 시스템 Python, 전투 작업자는 위 32비트 Python을 사용함. 계정 수집·원시 결과·분석은 모두 지정 비공개 폴더에 둠.

```powershell
$pw = '<workspace>/_env/venv-pw/Scripts/python.exe'
$battle = 'local/learned_reco/python32/python.exe'
$result = '<workspace>/_private/role-private/learned_reco'
& $pw -X utf8 tools/stage_reco_check.py collect --learned --out $result
python -X utf8 -I tools/learned_reco_measure.py native --collect "$result/collect.json" --out $result --python $battle
& $pw -X utf8 tools/learned_reco_measure.py browser --collect "$result/collect.json" --out $result
python -X utf8 -I tools/learned_reco_measure.py compare --out $result
```

`--methods F,A,C`·`--seeds 1,2,3`가 기본임. `--ids`로 수집 ID를 제한할 수 있음. 완료된 파일은 건너뛰므로 입력·도구가 달라지면 별도 출력 폴더를 써야 함. `collect --standard --learned --out local/learned_reco`는 지정 표준 3곳을 수집함. `--discover-hard`는 현재 표준 화면의 작전 25~49섹터 주요 스테이지와 회랑을 순서대로 탐침해 실제 전원 hard인 작전 2곳·회랑 1곳을 찾으며, 탈락 사유도 probe.json에 남김.

전투 실행 전에 여유 물리 메모리 6GiB를 검사하고 무거운 실행은 순차로 함. 브라우저 최대 메모리는 `bench_screen.MemPeak`, 네이티브는 Node+자식 전투 작업자 트리의 private commit 합계를 잼. 원시 JSON에 방법·시드·본선 확정 1위·독립 판별 값·단계별 비용·품질 감사·복귀·최대 메모리를 기록함. 비교기는 네이티브/브라우저의 예선 순서·1위 파티·브레이크·판 수·독립 결과가 같아야 통과함.

합성 시험은 `node tests/learned_reco_measure_test.js`임. 실제 화면 함수 조각으로 복귀 뒤 모든 요청이 F와 동일한지 검사함. 문턱 2개·독립 평가 재선택·복귀 시드 변경 변이 4개가 모두 실패함.

## 해석 범위

한 계정·세 스테이지의 결과임. 탐색 시드별 95% 구간을 다중 비교 보정 없이 따로 보고하며, 같은 독립 평가 시드를 쓰는 여러 탐색 결과를 서로 독립인 계정 표본처럼 합치지 않음. 같은 팀이 선택되더라도 사전 고정한 독립 재표집을 유지해 차이의 구간을 0으로 축소하지 않음. 표준 육성은 전제 미충족으로 제외했으므로 표준·다른 계정·저사양 기기로 일반화할 근거는 없음. 진단 최댓값은 판정에 쓰지 않음.
