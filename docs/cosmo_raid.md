# 코스모 게이트(RANKING_RAID) 시즌 시뮬 — 1단계(데이터+엔진)

시즌 1022(표 빌드 26429597): 벨그라스·티리아·카넬리아, 각 Step 1~3, 단일 웨이브·제한 50턴(전역 행동 수, CountEnemyTurnOnly=false), 전투 모드 BM_BOSS_KILL.
Step 3 에서만 난이도 레벨 1~18(레벨 3·6·9·12·15·18 에서 챌린지 효과가 하나씩 해금·누적).

## 파일
- `tools/build_cosmo_raid.py --tables <추출 폴더> --season 1022 --build <빌드>` → `data/cosmo_raid.json` (시즌 값 전부; 코드는 시즌 공통)
- `battlesim/starsavior/cosmo_raid.py` — 보스 정의(`build_waves`)·상태 기계(`Controller`)·점수(`cosmo_score`). 스위치 `mc.cosmo_raid_boss`(기본 off, api 의 `cosmo_raid` 전투에서만 자동 on)
- `cosmo_raid.js` — 점수 JS 구현(`cosmoScore`, `levelEffects`). `tests/cosmo_raid_test.py` 가 파이썬과 경계값까지 일치 확인
- `tests/cosmo_raid_test.py`

## API
`simulate(party, {"cosmo_raid": {"boss": "벨그라스|티리아|카넬리아"(또는 belgras|tyria|carnelia), "step": 1~3, "level": 0~18(Step 3 만)}}, options)`
(`options.cosmo_raid` 로도 받음. 아군은 `stats_override`(내 정보 능력치)를 쓰는 기존 경로 그대로.)
결과 최상위 `cosmo_raid`: `damage_frac_runs`(보스 깎은 HP 비율, 클리어 1), `remain_turns_runs`(클리어 판의 50 − 전역 턴, 아니면 0), `survivors_runs`, `clear_runs`, `turns_used_runs`, `score_runs`(판별 점수·추정), `ctl`(상태 기계 경로 횟수 합계), `approx`(근사 목록). 기존 `prog_runs`·`outcome` 등은 그대로.
점수: `cosmo_score(G, level, damage_frac, remain_turns, survivors, clear, boss, step)` / JS `cosmoScore(G, level, f, remain, surv, clear, boss, step)`.

## 확인된 것(표)
- Step 스탯(HP 56,000/84,000/1,000,000, ATK 2060/2940/5255, DEF 700/1400/3000, 속도 140/160/180)은 기존 databook `cosmo` N단계(티리아·카넬리아)와 같음(시험).
- 레벨 표(공격·HP·방어 배율, 점수 배율, 달성 점수 30만/60만)·챌린지 효과 이름·설명·해금 레벨·시즌 전투 버프 8057~8068.
- 벨그라스 수치: 연쇄 파열 160%·공허 붕괴 260%(쿨 4)·생기 약탈(쿨 4, 침식 35), 침식된 의지(속도 +1%·방어 +5%·궁극기 피해 +5%/중첩, 최대 35, 강인도 피해 무효), 썩은 의지(방어 −1%/중첩, 최대 50), 잠행하는 뿌리(속도 +50%·강인도 무효 1턴), 공허 붕괴 추가 고정 피해 5000×썩은 의지(최대 50), 잔멸의 가시(3턴, 시전자 공격력 10%/턴 시작), 끝없는 성장(+5%/스킬), 기록자·처단자(무적·속도 0 고정·공격 안 함, 응집된 생기 5중첩).
- 배치: 기록자(칸 0)·벨그라스(칸 2)·처단자(칸 4), 특수기만 사용 가능으로 시작(`SpecialSkillAvailable` true / `HyperSkillAvailable` false).

## «추정/근사» 목록 (영상·클라 코드 대조 전)
1. **점수 합산식**: HUD 식만 클라 근거(NKM:16914): clamp(기본 + 최대 피해 점수 × floor((maxHP−HP)×10000/maxHP) / 10000 내림, 0, 기본 + 최대 피해 점수), 매번 내림이며 엔진·`cosmo_score` 가 그대로 따름. 남은 턴·생존 구원자 항을 «클리어일 때만» 더하는지, 배율의 곱 순서·반올림(사사오입 가정), 달성 점수(HalfHPScore: 깎은 비율 ≥ 50%, KillScore: 클리어) 합산은 서버 계산이라 미확인(최종 합산·배율 반올림은 추정 유지). Step 1·2 는 배율·달성 점수 0 으로 둠.
2. **난이도 레벨 능력치 배율** = 능력치 × (1 + ScaleFactor/10000) (HP·공격·방어만, 속도·치명 등 불변). 곱 순서 미확인.
3. **시즌 전투 버프(BCT_*)**: 속성/직업이 맞는 아군에게 상시 효과로 부여(마커). 대상 해석이 맞는지 미확인. 생명력%는 전투 시작 때 최대치까지 채움.
4. **전투력 보정(power_penalty)**: 기존 코스모 N단계와 같은 권장 전투력(Step 행 BattlePower)으로 적용. 클라 코드에서 랭킹 레이드의 전투력 보정은 찾지 못함(없을 수도 있음, 미확인).
5. **챌린지 효과 12종**: 쇠락·시공·허무·분산·파쇄는 보스 효과(속도 +30%, 단일 피해 −20%, 강인도 피해 +1, 시작 3턴 면역, 타격자 최대 HP −5%/중첩 최대 10)로, 상흔(출혈 2턴, 효과 저항 판정 없음)·압박(기본기 타격 후 게이지 −20%)·진군(기본기 후 보스 팀 나머지 게이지 +25%)·역행(타임 패러독스 보유 중 피격 시 게이지 +8%)·역류(약화 보유 타격자에게 피격 시 +10%)·가시(궁극기 후 가시 추가 1개)·응징(궁극기 후 약화 보유 대상에 보스 공격력 30% 연쇄 피해)은 이벤트로 구현. «타격 후» 를 타격 1회가 아니라 시전 종료 시점으로 근사. 쇠락 상한은 «최대 10회»를 중첩 상한으로.
6. **벨그라스**
   - 초기 상태: 침식·썩은 의지·잠행 모두 0 (표에 초기 부여가 없어 보여 가정, 미확인).
   - 썩은 의지 발생 방지 체크 버프(BOSS_6)는 «효과 발생 전 상태(침식 또는 잠행 보유)로 판정»하는 근사.
   - 공허 붕괴의 추가 고정 피해: 타격한 아군 각각에게 5000×(썩은 의지, 최대 50) 방어 무시·보호막 적용으로 가정(대상 범위·보호막 적용 미확인). 시전 전 썩은 의지 수 기준, 시전 후 침식·썩은 의지 전부 해제.
   - 기록자/처단자: 무적이라 피해는 없고 응집된 생기만 줄음(단일 −1, 전체 −3). 0 이 되면 기록자=타격자 공격력 +50% 3턴, 처단자=아군 전체 보호막(대상 최대 HP 25%, 2턴)을 주고 영양 과잉 10턴(전역 턴). 재충전(상대 턴 시작)은 «영양 과잉 종료 후 다음 시전 종료 때»로 근사. 응집된 생기가 남은 동안 벨그라스가 공격하면 공격력 +50%(기록자, 2턴)·보호막 25%(처단자, 2턴) 부여(트리거 시점 «아군 타격» 해석 추정).
   - 가시 피해는 기존 지속 피해(DoT) 식(공격력 10%, 방어·상성·난수 적용, 같은 편 다른 유닛 0)을 사용.
   - 보스 대상 선택·스킬 우선순위는 기존 적 AI 규칙(길방·코스모와 동일 경로).
7. 티리아·카넬리아 Step 1~2 는 기존 databook 줄을 그대로 사용(이번 빌드 표와 스킬 설명 일치 여부는 이번에 대조하지 않음, 스탯만 대조).
8. 엔진에 없는 효과(예: 타임 패러독스 판정)는 가장 가까운 기존 효과 이름으로 대신함.
9. 시즌 버프(BCT) 대상 평가 코드는 클라에서 찾지 못함(3번의 대상 해석은 표 문구 기반 추정 그대로).
10. 고정 레벨 200·공명 10: 시뮬은 이미 `fixed200` 으로 반영(스타링크 가산 없음).
11. 보스 간 구원자 중복 금지: 클라가 막음(확인). 탐색의 겹침 금지 규칙과 일치.
12. 점수 초기화 재화 1000(표 값). 하루 도전·재도전은 제한 없음(사용자 확정) → 순위 기본은 «상위 점수».

## 2단계: 3보스 최고 점수 편성 찾기 (2026-11-06)
코스모 게이트 화면에 «3보스 최고 점수 편성 찾기» 패널(내 정보를 불러온 뒤). 난이도 레벨(0~18, Step 3)과 순위 기준(상위 점수 기본 = 판별 점수 상위 20% 평균 / 평균 점수는 선택. 재도전 제한이 없어 최고 점수가 목적)을 사용자가 고른다. 결과 표는 보스 3행(팀 4인·점수·클리어율·보스 깎음)과 합계, 2~5위는 접이식. «추정» 표시와 안내 문구 포함.

결정: 같은 구원자를 여러 보스에 쓰지 못함(12명 전부 다름) / 협공 제외는 적용하지 않음(코스모에 협공 금지 규칙 없음) / 점수는 판마다 점수식에 넣어 평균·상위를 냄(평균 값을 식에 넣지 않음).

흐름(`cosmo_search.js` `search`, 작업자 실행·후보 풀·조합·칸 순서는 `guild_search.js` 재사용):
1. 후보 풀 = **내 정보에서 육성된(전투력>0) 보유 구원자 전부(전수)**. 전투력 하한·역할 보충 없음 → 4인 조합(앞열 역할 ≥1, 딜러 ≥1) → 보스 3명 × 전 조합을 `screen.runs`(2)판. 시작할 때 앞열 역할 수 < 3×`minFront` 이거나 딜러 수 < 3×`minDealer` 이면 작업자를 띄우기 전에 부족한 쪽과 인원을 적은 오류로 멈춘다. 안전 장치: `maxPool`(숫자면 전투력 상위 N명 + `minRole` 보충으로 제한, 기본 null), `maxCombos`(보스당 조합 수 상한, 넘으면 시작하지 않고 안내).
2. 보스별로 상위 `rerank.keep`(300) 팀을 `rerank.runs`(20)판 재평가(상위 점수 = 20판 중 4판 평균. 실측 표준편차: 10판 0.8~1.6%, 20판 0.4~1.2%, 40판 0.3~0.9%라 10→20 으로 올림, 비용은 전체의 약 2%). 조합 수가 `keep` 의 2배 이하면 «상위 자르기+다양성 채우기»가 의미 없고 분할이 불발하므로 `keep` 을 조합 전체로 올린다(`effKeep`). 단순 상위 자르기는 «1위 구원자가 든 팀»만 남겨 3보스가 같은 구원자를 원하면 겹치지 않는 삼중이 없거나 나빠지므로, 절반은 순위대로 + 나머지는 구원자마다 «그 구원자가 든 최고 팀»을 돌려 가며 채움(`pickDiverse`).
3. 보스별 목록에서 겹침 없는 (A,B,C) 삼중의 합 상위 `combine.topTriples`(10)개를 분기한정으로 탐색(`bestTriples`, 비트 마스크; 전수 비교 시험으로 합·동점 순서까지 일치 확인).
4. 그 삼중에 든 팀을 `final.runs`(40)판 다시 돌려 합으로 재정렬, `combine.show`(5)개 표시.
작업자(`battlesim/web.py run_auto`)는 `options.cosmo_raid={boss,step:3,level}` 로 코스모 전투를 돌리고 결과에 요약 `cosmo={mean,top,clear,frac,n}`만 싣는다(판별 배열 없음, 반올림은 사사오입). 상위 비율은 `options.cosmo_top_q`(데이터 `search.topQ`).

**최적의 의미**: 결과는 «보스별 상위 `keep` 팀 안에서의 최적»이다(1단계에서 보스마다 상위 팀만 2단계로 넘기고 그 안에서 겹침 없는 3팀을 고름). 전체 조합의 수학적 최적은 보장하지 않는다(조합이 `keep` 의 2배 이하면 전부 넘기므로 그때는 전수 최적).

**search 조정**: 설정은 `data/cosmo_raid.json` 의 `search` 이고 값은 `tools/build_cosmo_raid.py` 의 `SEARCH` 상수에서 바꿔 다시 만든다(JSON 직접 수정 금지): `maxPool null`(전수), `maxCombos`, `minPowerRatio`·`minRole`(maxPool 을 줬을 때만 적용), `minFront`·`minDealer`, `screen.runs 2`, `rerank {keep 300, runs 20}`, `combine {topTriples 10, show 5}`, `final.runs 40`, `topQ 0.2`, `etaWeights`(단계별 한 판 상대 비용), `etaWarmupSec`(10), `etaWindowSec`(20), `etaWinFrac`(0), `etaBlendSec`(30).

**남은 시간 표시**(`cosmo_search.js` `plan`/`etaNew`): 전체 판 수는 시작 전에 안다 = 1단계(3×조합 수×`screen.runs`) + 2단계(3×keep×`rerank.runs`) + 3단계(상한 3×`topTriples`×`final.runs`, 단계 전환 때 실제 팀 수로 바로잡음). 속도는 «처음 결과가 온 뒤 `etaWarmupSec` 초는 쓰지 않고, 이후 최근 `etaWindowSec` 초 이동 구간»으로 재며, 아직 안 해 본 단계는 현재(또는 가장 최근 실측) 단계 속도 × 단계 가중치 비(`etaWeights`)로 추정하고 자기 속도가 측정되면 그 값으로 바꾼다. 단계 시작~첫 결과 지연(엔진 준비)도 남은 단계 수만큼 더한다. 완주하면 단계별 초/판과 작업자 수를 localStorage(`pn.cosmo.speed`)에 저장하고, 다음 시작 전 안내에 «예상 약 …»으로 쓴다(없으면 «시작하면 몇 초 뒤 예상 시간이 표시됩니다»). 저장된 속도가 있으면 측정 초반 `etaBlendSec` 초 동안 저장값과 섞는다(초반 속도는 엔진이 데워지는 중이라 낮게 나옴). 판 배분은 정적 분할이 아니라 작업 큐(`runPhase` 의 `chunk`, 팀 최대 50개씩 끝난 작업자에게 배분)라 끝 꼬리가 짧다. 진행 글자는 200ms 이상 간격으로만 바꾸고 취소 버튼은 다시 만들지 않는다. 내 정보 재불러오기·제외 목록 변경 때는 진행 중 검색을 취소하고, 끝난 결과에는 «낡은 결과»(내 정보 해시+제외 목록 서명 비교)를 표시한다.

판 수 추정: 조합 수 L = 앞열·딜러 조건을 만족하는 C(후보,4). 후보 40명(앞열 12)이면 L=70,420 → 1단계 약 42만 판 + 2단계 18,000판 + 3단계 ≤1,200판. 후보 수에 따라 급격히 늘므로(40명 7만, 57명 약 40만 조합) 시작 전 안내의 총 판 수·예상 시간을 확인한다. 실측값은 HANDOFF 코스모 절 참고.

시험: `tests/cosmo_search_test.js`(가짜 작업자: 겹침 금지·전수 최적·판 수·옵션·취소/오류), `tests/cosmo_web_test.py`(run_auto 코스모 분기·요약 반올림).
미검증: 실제 브라우저 화면·Pyodide 시간, 실제 내 정보로 나온 편성, 점수식 «추정» 항목(위 목록).
