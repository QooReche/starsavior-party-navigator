## 협공 상한과 후보 선정

`StatDataCap` 로더(T 29987)가 채운 객체를 최종 능력치 상한 함수(N 18397–18412)가 읽음. 버프 컨트롤러 합산(N 3859–3866)을 능력치 계산기로 전달하는 지점이 N 2371이며, 이 값은 N 18260/18291에서 최종 합에 들어간 뒤 N 18298에서 상한을 적용함. **전투 중 버프 합에도 StatDataCap이 적용됨.**

현재 제공된 `tables/Plain/CLIENT_CONST_TEMPLET.json:138–142`에서 협공 3000은 주석임. 양수 상한만 적용하는 함수와 N 15635의 `RollDice(value, 10000)`를 함께 보면 확률만 100%로 제한하는 기존 `COOP_CAP=1.0`과 같음. 별도 `JSON_STAT_DATA_CAP`의 값으로 런타임 상한을 대체하지 않았음.

협공 후보 선정은 같지 않았음. 새 N 15508–15518은 다음 순서임.

1. 생존 아군에서 본 행동자 제외.
2. 강제 협공 상태의 사용 가능 후보가 있으면 그 집합에서 균등 추첨.
3. 일반 협공은 후보별 기본기 사용 가능·브레이크·`DisableCrossAttack` 확인 후 각각 확률 판정.
4. **모든 성공 후보를 목록으로 만든 뒤** `ArrayIndex(count)`로 한 명 선택. 확률순 정렬이나 첫 성공 반환이 아님.

이번 `coop_order` 구현은 일반 협공 선정에 적용했음. `협공 불가`는 현재 BUFF_TEMPLET ID 1531의 `DisableCrossAttack`임. `stat`과 `capped` 재현 모드의 동작은 보존했음. MC에서는 슬롯순으로 전원 판정하고 `choice`로 선택함. 정수 난수인 클라와 시드별 동일성은 보장하지 않음.

기대값 엔진도 후보별 성공 확률을 단순 정규화하지 않았음. 후보 i의 몫은 `p_i × Σ(P(다른 성공자 k명)/(k+1))`임. 예를 들어 확률 0.5/0.8/0.2이면 몫은 0.276666…/0.546666…/0.096666…이며 합은 최소 한 명 성공할 확률 0.92임. 후보 전원이 100% 이상이면 동등한 몫을 가짐. 강제 협공이 이미 차지한 기대 비율은 기존처럼 제외함.

새 클라의 강제 협공 상태 집합 선정과 기존 `forced_coop_target`의 공격력 대상 선정은 구분했음. 프로페서M 효과가 특정 대상에 상태를 부여하는 경로·복수 강제 협공 상태의 완전한 재현은 이번 일반 협공 변경에 포함하지 않았음.

## 강화 거부·개수·피격 순서

- 노바 최대 12 반영, SE 단위 강제 약화 적용, 복수 강제 협공 상태와 대상 선정은 별도 후속 범위임.
- 기존 버프 이름 충돌 폴백·기대값 엔진의 상태 및 피해 가중 근사는 유지했음. 새 줄 번호 확인이 전체 엔진의 완전한 일치를 뜻하지 않음.
- 협공 기본값이 바뀌었으므로 화력표·빠른 계산 계수·길방 시뮬 표는 통합 뒤 **재생성 필요**함. 생성 금지 지시에 따라 이번에는 보고만 했음.
- HANDOFF.md·AGENTS.md는 수정하지 않았음. HANDOFF 초안은 최종 보고로 전달하기로 함. 푸시하지 않기로 함.
