# 실측 기록(보정용)

시뮬레이터가 실제 게임과 얼마나 맞는지 확인하려고 인게임 전투 결과를 모은다. 설계 근거는 `docs/battlesim_design.md` 6절.

## 어디서 기록하나
- **코스모 게이트·플래시 포인트**만(레벨 200·공명 10 고정이라 시뮬 조건과 겹친다).
- 10/22 패치 전 작전 보스 결과는 쓰지 않는다(보스 공격력 하향 예정).

## 형식 — `cases.jsonl`, 전투 1건 = 1줄
`cases.example.jsonl` 을 복사해 고쳐 쓴다. 모르는 칸은 `null`.

| 칸 | 뜻 | 예 |
|---|---|---|
| date | 날짜 | `"2026-10-21"` |
| patch | 게임 버전(설정 화면) | `"2.50"` |
| content / stage | 콘텐츠·스테이지 이름(게임 표기 그대로) | `"코스모 게이트"`, `"길레 2단계"` |
| party | 4명, 배치 순서 전열1·전열2·후열1·후열2 | `["그웬","아모라","페이","프로페서M"]` |
| leader | 리더 | `"페이"` |
| potentials | 구원자별 잠재력(알면) | `{"그웬":["성흔"]}` |
| auto | 오토 전투였나 | `true` |
| nova_burst | 노바 버스트를 눌렀나(오토면 false) | `false` |
| clear | 클리어했나 | `true` |
| clear_turn | 클리어 턴(화면 턴 표시) | `6` |
| deaths | 쓰러진 구원자와 턴 | `[{"who":"페이","turn":4}]` |
| end_hp_pct | 끝났을 때 남은 HP %(전열1부터) | `[40,100,0,85]` |
| damage_shown | 결과 화면 피해량(있으면) | `{"그웬":120345}` |
| notes | 특이사항(브레이크 몇 턴, 협공 횟수 등) | `"3턴에 보스 브레이크"` |

## 사용자 관찰 기록
- 2026-10-20: 오토 전투에서 아군은 **보스를 먼저 친다**(사용자 관찰). → 시뮬 아군 오토 대상 = 보스 우선, 그다음 보호막+HP 가장 낮은 적.
  그래서 단일 공격만 있는 파티는 보스 좌우 쫄몹이 오래 살아남아 계속 때리는 경우가 있다 → 광역 공격 유무가 생존·처치 턴에 드러나야 한다(검증 항목).

## 짧은 관찰 실험(모르는 규칙 확인용, 각 10~20회면 충분)
1. **노바 포스가 팀 공용인가**: 서로 다른 구원자가 특수기를 쓸 때 노바 칸이 하나로 쌓이는지(1판이면 판정).
2. **적이 누구를 때리나**: 적 단일 공격 20회의 대상(전열/후열, 디펜더 여부) 집계.
3. **협공 빈도**: 아군 기본기 10회당 협공 횟수, 기본기 말고 다른 스킬 뒤에도 나오는지.
4. **보스 브레이크까지 몇 번**: 강인도가 0 이 될 때까지 쓴 스킬 목록.
5. **지속 피해에 공격력 버프가 붙나**: 같은 연소 틱을 버프 있을 때·없을 때 비교.
가능하면 녹화해서 처음 5~10행동(누가·누구에게·무슨 스킬·피해·HP/보호막·강인도)을 notes 에 적는다.
