## 생성·채택

내장 `image_gen`, `transparent_background=true`로 종별 3칸 원화 시트를 생성했음. 1칸은 기본 자세, 2칸은 그린 동작 원화, 3칸은 깜빡임 합성용 원화임. 호출 전체 프롬프트·수정 이유는 [prompts5.json](prompts5.json)에 있음. 공식 참고는 외부 경로에서 보기만 했으며 커밋 대상에 넣지 않았음. 도구 기본 생성 캐시의 결과를 이 worktree의 `_tmp/art5/`로 복사했음.

## 원화·재생·알파

[build5.py](build5.py)는 build2 방식으로 3칸을 공통 경계로 자르고, 같은 축척·기준선으로 320px 칸에 정규화함. `masters5/<name>.webp`는 960×320 원화 시트임. build3와 같은 알파 10 미만 잡음 제거·245 초과 불투명 정리를 하고 가장자리 알파를 보존했음. 원화도 80,000B 이하로 저장하려고 WebP quality 90부터 88·86·84·82 순으로 검사함. 채택본은 cry·ok만 88, 나머지는 90임. API 없이 커밋된 원화로 재현함.

화면용 `assets/ui_icons/gwen/<name>.png`·`.webp`·`_blink.png`는 모두 240×240임. 정지 PNG는 build2의 256색 RGB 양자화 후 원본 알파 복원을 그대로 사용함. 동작은 기본→동작→기본 3프레임, **450/220/330ms = 1초, loop=1**임. 마지막은 기본 자세로 돌아가 정지함. WebP 인코더는 기존 quality=88/method=6임.

wink는 두 번째 원화의 윙크 눈 영역만, zap은 두 번째 원화의 스파크 영역만 기본 원화에 합성했음. 이 둘은 몸·손·소품의 불필요한 흔들림을 없앴으며 해당 동작 마스크 밖 픽셀 동일성을 검사함. 다른 8종은 새로 그린 두 자세를 사용함. 캐릭터를 코드로 새로 그리지 않았음.

[blink_masks5.json](blink_masks5.json)의 320px 눈 다각형 안에서만 세 번째 원화를 합성함. 240px 마스크는 Lanczos 축소의 영향 범위까지 포함함. 원화·화면용 PNG 모두 눈 마스크 밖 RGBA와 전체 알파가 기본 그림과 바이트 단위로 같음. 눈 영역 면적은 4% 미만임. 기본 자세부터 감은 눈인 cry는 일반 개폐 대신 눈을 더 질끈 감는 동반 프레임임. wink의 정지 PNG는 윙크 전, 동작 두 번째 프레임이 윙크, `_blink.png`는 양눈 감음임.

깜빡임 파일은 단일 정지 PNG임. 120~160ms 표시·쉬는 간격·실제 표시 시 재생은 기존 화면 소비자의 역할이며 이번에 연결하지 않았음. 화면 코드·index.html은 수정하거나 재생성하지 않았음.

## 실측·예산·병합

대표 cry·verdict를 먼저 정규화·인코딩했음. 초기 PNG+WebP는 각각 **104,534B / 96,387B**, 깜빡임 포함 **156,661B / 145,290B**였음. 대표 큰 값에 약 8.5% 여유를 둔 종당 170,000B × 10종으로 추가 예산 **1,700,000B**를 배정했음. cry 원화의 80,000B 준수 압축을 적용한 최종 바이트는 아래 표임.

한도 정본은 [budget.json](budget.json) 한 곳임. 기존 `file_bytes=80000`을 유지하고 전역 `served_bytes`는 기존 1,450,000 + art5 배정 1,700,000 = **3,150,000B**로 변경했음. art3의 기존 배정·실측 키는 그대로 두고 새 근거는 별도 `art5` 객체에만 추가했음.

art4 병합 시 `art5` 객체를 보존하고 art4의 별도 배정 키도 보존함. 공통 `served_bytes` 한 줄만 충돌할 수 있으며 한쪽 값을 선택하면 안 됨. 공통 기준 한도 1,450,000B에 art4와 art5의 추가 배정을 각각 한 번씩 더하고, 합쳐진 파일의 실측 및 전체 시험으로 검증함. 이 worktree에서는 다른 worktree를 읽거나 수정해 합산하지 않았음.

새 화면용 30파일은 **1,340,973B / 1,700,000B**, 여유 359,027B임. 전체 화면용 86파일은 **2,623,875B / 3,150,000B**, 여유 526,125B임. 새 화면 파일 최대 53,590B, 원화 포함 최대 78,364B임. 원화는 화면 합계에서 제외함.

## 비교·검증

`_tmp/_art_compare5.png` 및 `_tmp/art5/compare_<name>.png` 행별 원본 크기 시트를 `view_image`로 직접 확인했음. 기존 confident·thoughtful·notes와 10종을 같은 어두운 배경에서 120·160·240px, 동작 원화 2개, 깜빡임으로 비교했음. 환호의 팔 전환과 OK의 잔여 배경만 수정한 뒤 다시 확인했음. 비교 시트·원본 생성물·로그는 커밋하지 않음.

Pillow **12.3.0**, libwebp **1.6.0**에서 검증했음. 같은 인코더 버전에서 바이트 재현함.

```powershell
python -B -X utf8 tools/gwen_art/build5.py --compare
python -B -X utf8 tools/gwen_art/build5.py --check
python -B -X utf8 -I tests/gwen_art5_test.py
python -B -X utf8 tools/gwen_art/mutations5.py
python -X utf8 -I tools/run_tests.py
```

새 자산 시험 5개: 40개 원화·화면 파일 존재/규격/파일 한도/진짜 알파/가장자리 여백, 동작 프레임 변화/1초/loop=1/기본 자세 복귀, wink·zap 국소 변화, 깜빡임 마스크 밖 동일, 예산 및 전체 기존 자산을 포함한 빌드 전후 SHA-256 동일을 검사함.

되돌림 검출은 [mutations5.py](mutations5.py)로 재현함. 파일 누락·크기 축소·알파 불투명화·파일 한도 초과·동작 정지화·loop=0·900ms 첫 프레임·깜빡임 원본 대체·눈 밖 픽셀 변조 **9종 모두 실패를 검출**했음. 각 변조는 finally로 원복하고 40개 파일의 SHA-256 동일을 확인했음. 로그는 `_tmp/art5/mutation-*.log`·`mutations.log`임.

기준 전체 실행은 새 대표 파일 추가와 겹쳐 용량 검사만 실패했음(185통과/1실패). 새 파일을 잠시 분리하고 HEAD의 예산으로 실행한 원래 자산 시험 7개는 모두 통과했으며 파일·예산을 원복했음. 최종 `python -X utf8 -I tools/run_tests.py` 결과는 **187통과/실패0**임. `COSMO_TABLES` 부재로 `cosmo_raid_test.test_data_matches_tables` 1건은 건너뛰었음. 로그는 `_tmp/art5/final-tests.log`이며 새 `gwen_art5_test.py`와 기존 `gwen_art_test.py` 모두 통과했음.

남은 범위: 화면 연결·실제 브라우저의 재생 타이머·깜빡임 표시 시간·첫 로드 전송량은 이번 그림 작업에 포함하지 않았음. art4와 합친 예산은 병합 후 실측해야 함. 공식 원화와 생성된 팬 그림 사이의 세부 차이는 남을 수 있음.
