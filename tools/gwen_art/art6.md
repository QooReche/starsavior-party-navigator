### 직접 본 구간과 좌표

`_tmp/_art_sleeve8_notes.png`를 직접 열어 확인했음. **각 그림은 전체 캔버스 480×480px**, 위 행 수정 전·아래 행 수정 후, 열은 PNG/F0/F1(눈감기)/F2임. 시트 크기는 1920×1020. 좌표는 **배포 원본 240×240의 왼쪽 위 (0,0), 화면 기준**이며 480px 셀 안에서는 각 값을 2배 함. 시트 절대좌표는 열×480과 행×510+30을 더함.

| 프레임 | 화면 왼팔: 보이는 흰 띠 경로 | 화면 오른팔: 보이는 흰 띠 경로 |
|---|---|---|
| PNG·WebP F0·F2 | 어깨 아래 (66,146) → 바깥 위팔 (56,182) → 팔꿈치 (58,194) → 전완 (69,188) → 손목 프릴 앞 (83,177)~(86,175). 수정 전 전완 연결 구간이 파란 천으로 끊겼음 | 어깨 아래 (180,148) → 위팔 (180,165) → 접힘 (184,182) → 팔꿈치 (185,196) → 굽은 띠 (180,203) → 전완 (169,198) → 프릴 앞 (162,195)~(160,193). 수정 전 이 바깥면 전체에 흰 띠가 없었음 |

오른팔의 y=148~169에서 띠는 대략 x=177~183, 팔꿈치 y=196에서는 x=182~187, 전완 y=199에서는 x=165~176에 보임. 왼팔 전완은 (69,188)과 (83,177)을 잇는 넓은 흰 면으로 확인함. 푸른 천의 검은 외곽선과 프릴은 남겨 두었고, 어깨 견장 뒤·손과 프릴 아래만 가려짐. 굵기는 원근에 따라 약 5~11px로, 참조의 바깥면 넓은 띠와 같은 배치임. 단일 색 점만 보고 판정하지 않고 어깨→팔꿈치→프릴 경로의 연결과 실제 시트를 함께 확인했음.

notes는 원래 별도 `notes_blink.png`가 없음. **정지 1장과 WebP F0/F1/F2, 총 4장** 모두 수정했으며 F1이 깜빡임임. 다른 캐릭터 그림은 바꾸지 않았음.

### 픽셀 보존·용량·검증

정지 PNG의 소매 마스크 밖 RGBA는 원본과 완전 동일함. WebP는 이번에 **무손실**로 저장해 소매 밖 모든 보이는 픽셀(alpha>0)의 RGBA, 얼굴·메모장·양손과 **모든 알파 값**이 각 수정 전 디코딩 프레임과 정확히 같음. 완전 투명(alpha=0) 영역의 숨겨진 RGB는 WebP 인코더가 0으로 정리하므로 보존 대상에서 제외했음. 소매 외부의 보이는 압축 오차는 없음. 기존 art7의 손실 재인코딩 한계는 이번 notes에 적용되지 않음.

원본 디코딩 WebP만 무손실 저장해도 127,624B였음. 픽셀 보존 요구를 위해 **notes.webp에만 140,000B 한도**를 추가했음. 실제 132,892B, 다른 파일 기본 80,000B와 전체 3,150,000B 한도는 유지함. 전체 실제 2,754,807B임. 시험의 모든 파일 한도 검사는 유지하고 이 파일만 명시적인 예외값을 검사함. 이전 provenance7의 notes 미수정 기록은 `superseded_by_art8`로 이동하고 [provenance8.json](provenance8.json)의 원본 검증으로 인계했음.

내장 image_gen 편집 **3회, 그림별 1회**, 재생성 없음. 전체 지시·입력·캐시 경로는 [prompts7.json](prompts7.json). 결과 전체를 교체하지 않고 [patches7](patches7)의 무손실 소매 조각과 다각형만 적용함. point/sulk는 첫 편집 셀의 소매를 동작 위치에 맞춰 이동해 일관성을 유지했음. 모든 원화 WebP 파일은 그대로임. [sleeve7.py](sleeve7.py)를 build5/6과 기존 build2에 연결해 API 없이 재현함.

인코딩 전 원화와 point/sulk 정지·깜빡임 PNG는 **소매 마스크 밖 RGBA와 전체 알파가 원본과 동일**함. PNG 팔레트가 소매 변경 때문에 얼굴 색까지 바꾸지 않도록 원본 팔레트를 재현하고, 깜빡임 눈도 원본 팔레트에서 합성함. thoughtful 정지 PNG와 WebP F0/F2는 원본 그대로임. 나머지 10종 배포 파일은 바이트 단위 동일함. [provenance7.json](provenance7.json)에 수정 전 PNG의 마스크 밖 해시와 미수정 자산 해시를 기록했음.

**WebP의 소매 밖 RGB 픽셀 완전 보존은 충족하지 못함.** 기존 quality 88 손실 인코더를 유지하므로 재인코딩 차이가 남음. 원본 디코딩 프레임을 무손실로 저장하는 시험만으로도 point 117,896B·sulk 113,564B여서 기존 개별 80,000B 한도를 넘었음. 한도는 바꾸지 않았음. 최종 WebP의 모든 알파는 수정 전과 동일함. 이 차이는 생성 결과로 얼굴을 교체한 것이 아니라 손실 압축 차이임.

## 생성·도야가오 선택

내장 image_gen 총 18회: 12종 첫 생성 + thoughtful 소매 편집 1회 + st_verdict 재생성 1회 + st_cry 소매 편집 1회 + 도야가오 독립 후보 3회. 본 그림별 최대 2회임. SD는 생성·수정하지 않았음.

- thoughtful: 첫 결과의 보는 사람 왼쪽 전완 안쪽에 흰 띠가 생겨 편집했음. 편집 결과가 바깥 위팔 띠도 없애서, 새로 생성한 첫 원본에 편집된 전완 영역만 합성했음. 얼굴·다른 의상은 첫 결과 그대로임.
- st_verdict: 첫 결과가 채찍을 반대 손에 들어 제외했음. 두 번째 결과는 원래 설계대로 오른손(보는 사람 왼쪽)의 정면 지목이며 핀 방향도 유지했음.
- 다른 10개 재생성 대상과 st_cry는 첫 결과를 채택했음. st_cry는 편집 결과의 소매만 쓰고 얼굴·머리·몸통·손은 승인 원본을 사용했음.

도야가오 후보 10°·18°·25°를 실제 생성하고 `_tmp/_art_doya6.png`에 각각 120·160·240px로 배치해 직접 봤음. 각도는 생성 지시값이며 실측 3D 각도가 아님. **18° 채택**: 10°보다 턱 들기·아래로 내려다보는 시선이 분명하고, 25°보다 얼굴과 목의 비율이 자연스러움. 25°는 턱 아래 면과 목이 강해져 공식의 작고 부드러운 얼굴 느낌이 약해짐. 채택본은 콧구멍 노출 없이 의기양양한 인상이 작은 크기에서도 읽힘. 단순 2D 회전으로 각도를 대신하지 않았음.

## 후처리·얼굴 보존·재현

[build6.py](build6.py)는 커밋 대상 masters2의 기존 3종·masters5의 9종 새 원화와 기존 st_cry 원화 및 [patches6](patches6)의 소매 패치로 API 없이 재현함. 원화는 320px 칸, 화면용은 기존 240×240 PNG/WebP이며 450/220/330ms·1초·loop=1 그대로임. masters5는 기존 알파 잡음 제거·정규화·quality 90→88 등 파일 한도 인코딩을 사용했음. OK·wink 원화는 quality 88, 나머지는 90임. 화면 인코더 quality 88·method 6, 정지 PNG RGB 양자화 후 알파 복원 규칙도 유지했음.

st_cry 원화 파일은 변경하지 않았음. [cry6.py](cry6.py)가 3개 프레임의 지정 소매 다각형에만 14,420B 무손실 WebP 패치를 적용하고 원본 알파를 복원함. 승인된 원래 정지·깜빡임 PNG를 비배포 보존 자료로 두고, 새 화면용 PNG에서도 소매 마스크 밖 RGBA를 바이트 단위로 보존했음. 눈·얼굴·머리는 같음. **손실 압축 애니메이션 WebP의 디코딩 픽셀은 재인코딩 때문에 원본과 완전 동일하다고 보장하지 않음**. 인코딩 전 3개 원화와 배포 정지·깜빡임 PNG의 보존은 시험으로 확인함. 원본 애니메이션의 얼굴 디코딩 픽셀을 복원한 무손실 시제품은 141,926B로 80,000B 한도를 넘어 채택하지 않았음(`_tmp/art6/cry-exact-animation.webp`).
