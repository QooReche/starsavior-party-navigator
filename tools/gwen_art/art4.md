## 생성·채택·반전

전체 지시는 [prompts4.json](prompts4.json)에 있음. 새 원화 생성 10회(달리기 4칸 시트·점프 2칸 시트 포함), 감은 눈 편집 7회임. 모두 첫 결과를 채택했으며 **원화·깜빡임 재생성 0회**임. 전연령, 문자·로고·배경·바닥 그림자 없음. 채찍은 이번 추가 그림에서 사용하지 않았고 스턴건은 충전 소품으로만 사용했음. 외부 공식 레퍼런스는 복사·커밋하지 않았음.

| 이름 | 채택 확인 |
|---|---|

| jump | 오른쪽 옆모습, 발을 접은 공중 자세와 무릎 굽힌 착지 자세. |
| guide2 | 양옆의 열린 손바닥으로 두 선택지를 안내함. |
| present | 한 손바닥으로 옆 대상을 소개함. |

## 후처리·재생 계약

[build4.py](build4.py)는 art3와 같이 알파 10 미만 잡음을 없애고 245 초과를 불투명으로 정리하며, 중간 가장자리 알파를 유지함. 정지 원본은 512px, 화면 파일은 160px임. 모두 여백이 있는 동일 캔버스이며, 기존 원본·화면 파일은 바꾸지 않았음.

run·jump는 한 시트 안의 모든 프레임에 같은 축척을 적용했음. run의 최대 높이는 450px, jump는 공중 여백을 위해 410px임. run은 포즈별 발 위치를 공통 바닥선에 놓았음. 정규화 뒤 512px 팔레트 변환에서 반투명 끝 픽셀 차이로 1px 편차가 생겨, 알파 ≥128의 발 끝 경계 y=482로 정렬했음. 160px Lanczos 축소에서도 같은 경계가 1px 달라져 출력 시 y=151로 다시 평행 이동했음. 개별 프레임 축척을 바꾸지 않았음. 투명도 0보다 큰 모든 픽셀의 끝은 필터 영향으로 다를 수 있으며, 시험은 눈에 보이는 반불투명 경계를 기준으로 함.

| 이름 | 프레임·시간 | loop | 동작 |
|---|---|---:|---|
| run | 4 × 200ms = 800ms | 0 | 번갈아 뻗고 접는 다리·펌핑하는 팔의 연속 루프 |
| point | 300/200/200/300ms = 1초 | 1 | 가리키는 손·손목을 조금 움직인 뒤 원위치 |
| jump | 400/600ms = 1초 | 1 | 공중 → 착지, 마지막 착지에서 종료 |
| guide2 | 300/200/200/300ms = 1초 | 1 | 열린 한 손을 가볍게 움직임 |
| present | 동일 | 1 | 내민 손바닥을 조금 올렸다 원위치 |
| train | 동일 | 1 | 덤벨을 쥔 팔을 0/−8/−16/0도로 들어 올림 |
| charge | 동일 | 0 | 단자 사이 스파크 픽셀만 밝기 변화 |
| wait | 동일 | 0 | 무릎 아래 두 다리를 반대 방향으로 작게 흔듦, 얼굴·몸·의자 고정 |
| peek | 동일 | 1 | 숙인 머리를 작게 끄덕임 |
| wake | 동일 | 1 | 감은 눈 → 뜬 눈으로 8px 들썩 → 3px → 정지 자세 |

loop=0은 연속, loop=1은 1회임. `jump.png`는 공중 정지 자세임. 착지 원본은 `frames4/jump_1_512.png`이며 WebP 마지막 프레임에도 있음. `wake.png`는 눈을 뜬 정지 자세이고 WebP 첫 프레임은 감은 눈이므로 서로 다름. 나머지 정지 PNG는 동작 첫 자세임.

덤벨 검수 중 투명 픽셀의 RGB가 보이는 원본 미리보기에서 잔상이 의심됐으나, 실제 알파를 어두운 배경에 합성한 결과는 정상임을 확인했음. 덤벨 상승 시험의 초기 범위가 머리카락까지 포함해 실패하여, 회색 추의 위쪽 경계를 검사하도록 수정했음. 원화를 다시 그리거나 잔상을 덧칠하지 않았음.

## 깜빡임

guide2·present·train·charge·wait·peek·wake 7종임. [blink_masks4.json](blink_masks4.json)의 눈 다각형 안에서만 생성한 감은 눈을 가져오고, 원본 알파를 복원함. 패치는 `blinks4/*_eyes_512.png`의 이진 알파 마스크임. 512px 합성·160px `_blink.png` 모두 마스크 밖 RGBA가 원본과 바이트 단위로 같음. 160px 마스크는 Lanczos 필터 영향 범위까지 포함하며 캔버스의 약 2.8~3.2%로 4% 미만임.

깜빡임은 단일 정지 PNG임. 표시 120~160ms·반복 간격은 화면 연결 단계의 범위이며, 행동 WebP의 프레임당 200ms 이상 규칙과 별개임.

## 재현·검증

Pillow **12.3.0**, libwebp **1.6.0**에서 검증했음. 바이트 재현은 같은 인코더 버전 기준임.

```powershell
# 커밋된 원본·눈 패치에서 재현
python -B -X utf8 tools/gwen_art/build4.py --compare
# 수정 없이 검사
python -B -X utf8 tools/gwen_art/build4.py --check
# 최초 채택 원화 가져오기만 필요할 때
python -B -X utf8 tools/gwen_art/build4.py --import-dir _tmp/art4 --masters-only
python -B -X utf8 tools/gwen_art/build4.py --import-blinks _tmp/art4 --compare
python -B -X utf8 -I tests/gwen_art_test.py
python -B -X utf8 tools/gwen_art/check_mutations4.py
python -X utf8 -I tools/run_tests.py
```

`_tmp/_art_compare4.png`와 행별 `_tmp/art4/compare-*.png`를 직접 확인했음. 승인 investigate·ready·walk와 새 10종, 64·72·120·160px, 어두운 배경, 감은 눈, 좌우 반전, 저장된 WebP의 모든 프레임·시간을 포함함. 축소 표정·알파 경계·덤벨·의자·스파크·좌우 손짓을 확인했음. 비교 시트·생성 원본·검수 보조 이미지·로그는 커밋하지 않음.

자산 시험 **13개 통과**(기존 7+신규 6)임. 신규 48파일의 존재·크기·실제 알파·반투명 가장자리·한도, 동작 프레임 변화·개수·loop·시간, run 원본/출력 바닥선, jump 높이, train 상승, wait·charge 부위 제한, 눈 마스크 밖 동일, 48파일 재빌드 SHA-256 동일을 검사함. 눈 패치는 의도적으로 이진 알파이므로 반투명 가장자리 검사만 제외함.

[check_mutations4.py](check_mutations4.py)로 실제 파일을 하나씩 깨뜨려 아래 9종의 실패를 확인했음. 각 검사 뒤 `finally`에서 원래 바이트를 복원하고 SHA-256 일치를 확인함. 개별 로그는 `_tmp/art4/mutation-*.log`, 결과는 `mutations.json`임.

## 남은 범위·위험

화면 코드(ux_ui.js·ux.css·party_template.html·index.html)는 수정·재생성하지 않았음. UI 연결, 브라우저에서 1회 재생을 다시 시작하는 타이머, 이동 속도와 run 루프 조합, 실제 첫 로드 전송량·레이아웃·reduced-motion 동작은 이번 자산 작업에서 검증하지 않았음. point 반전 시 핀·리본의 좌우도 바뀌는 것은 채택한 연출 결정임. 작은 스파크는 64px에서 약하게 보이며 charge는 소품을 모아 든 정지 자세로도 구분됨.
